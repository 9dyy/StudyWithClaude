SECTION 01 · 버그

1히트 판정에서 터진 캐스팅 버그

총알이 뭔가에 맞았다. AWeaponPickup이면 무기를 교체하고 싶다.

void ABullet::OnHit(AActor* HitActor)
{
    AWeaponPickup* Weapon = (AWeaponPickup*)HitActor;   // C-style cast
    Weapon->EquipTo(OwnerCharacter);                    // 크래시 혹은 이상한 동작
}

빌드는 잘 된다. 그런데 총알이 AWall에 맞으면 게임이 죽는다. HitActor가 진짜 AWeaponPickup인지 아무도 확인을 안 했기 때문이다.

SECTION 02 · 지도

2네 형제 소개 — 뭘 검사하고 뭘 안 하나

캐스팅하는 일런타임 검사실패 시
static_cast컴파일러가 "관련 있다"고 아는 타입끼리 변환❌ 안 함조용히 틀린 결과(UB)
dynamic_cast실제 객체 타입을 런타임에 확인하며 변환✅ RTTI로 확인포인터는 nullptr, 참조는 예외
reinterpret_cast타입 무시하고 비트를 그대로 재해석❌ 안 함정의조차 안 됨(대부분 UB)
const_castconst/volatile 속성만 떼거나 붙임❌ 안 함원본이 진짜 const면 UB

공통 원칙: 컴파일러가 검사해줄 수 있는 건 컴파일 타임에, 실제 객체 타입을 봐야 아는 건 런타임에 검사한다.

SECTION 03 · 핵심 비교

3static_cast vs dynamic_cast

static_cast — "관련 있는 건 아는데, 진짜 그 타입인진 안 봐"

AItemActor* Item = static_cast<AItemActor*>(Weapon);   // 업캐스팅. 항상 안전
AWeaponPickup* Back = static_cast<AWeaponPickup*>(Item);  // 다운캐스팅. 컴파일은 됨. 검사 안 함!

업캐스팅은 자식 안에 부모가 통째로 포함된다는 게 타입 시스템으로 보장되니 검사가 필요 없다. 문제는 다운캐스팅 — "확실히 알고 있다"는 전제가 있을 때만 써야 한다.

dynamic_cast — "진짜 그 타입인지 런타임에 확인하고 변환"

void ABullet::OnHit(AActor* HitActor)
{
    AWeaponPickup* Weapon = dynamic_cast<AWeaponPickup*>(HitActor);
    if (Weapon != nullptr)   // 진짜 AWeaponPickup일 때만 nullptr이 아님
    {
        Weapon->EquipTo(OwnerCharacter);
    }
}

가상 함수가 있는 클래스는 객체마다 vtable 포인터를 갖고, 그 근처에 RTTI(실제 타입 정보)가 심어져 있다. dynamic_cast는 이걸 뒤져서 확인한 다음에야 포인터를 내준다 — 그래서 static_cast보다 느리다.

SECTION 05 · 나머지 형제

5reinterpret_cast · const_cast

reinterpret_cast — "타입 신경 안 써, 비트를 그대로 다르게 읽어"

uint32 RawColor = 0xFF00FF00;
uint8* Bytes = reinterpret_cast<uint8*>(&RawColor);   // 바이트 단위로 뜯어보고 싶을 때

네트워크 패킷 버퍼 파싱 같은 저수준 메모리 조작에만. 일반 게임플레이 코드에 보이면 십중팔구 설계가 잘못된 신호.

const_cast — "타입은 그대로, const만 떼거나 붙여"

void PrintMessage(const char* Msg)
{
    LegacyLogFunction(const_cast<char*>(Msg));   // const를 떼서 넘겨줌
}

원본이 진짜 non-const였는데 const를 거쳐온 경우에만 안전. 원본 자체가 const로 선언된 객체를 떼고 값을 바꾸면 UB.

SECTION 06 · 언리얼 실전

6언리얼의 Cast<T> — 내부적으로 뭘 쓰나

// Cast<T>의 개념적 동작
template<typename T>
T* Cast(UObject* Obj)
{
    if (Obj && Obj->IsA(T::StaticClass()))   // UClass 기반 타입 확인
        return static_cast<T*>(Obj);          // 확인 끝났으니 이제 안전
    return nullptr;
}

언리얼은 표준 RTTI를 꺼두고 UClass/IsA() 기반 자체 타입 시스템으로 대체했다. 목적은 dynamic_cast와 같고, 확인 방법만 다르다.

void ABullet::OnHit(AActor* HitActor)
{
    if (AEnemyCharacter* Enemy = Cast<AEnemyCharacter>(HitActor)) { Enemy->TakeDamage(...); return; }
    if (AWeaponPickup* Weapon = Cast<AWeaponPickup>(HitActor)) { Weapon->DestroyByImpact(); return; }
    if (AExplosiveBarrel* Barrel = Cast<AExplosiveBarrel>(HitActor)) { Barrel->TriggerExplosion(); return; }
    Destroy();   // 벽, 바닥 등 — 아무 반응 없이 총알만 파괴
}

각 Cast<T>는 실패하면 nullptr만 리턴하고 다음 줄로 넘어간다 — 크래시 없음. 단, 분기가 5개, 10개로 늘어나면 Cast 체인 대신 인터페이스(IDamageable)와 가상 함수로 푸는 게 정석이다.
