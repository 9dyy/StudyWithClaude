Attack의 if문을 없애라

몬스터 A·B·C가 각자 Attack을 구현하는데, 호출할 때마다 if문으로 종류를 찾고 있다. 10강이 "상태별 if-else"를 풀었다면 이건 "종류별 if-else"다. 가상 함수가 vtable로 어떻게 분기를 대신하는지 직접 눌러 확인한다.

🎯 실제로 받은 질문
🧩 선수지식 2강 · 10강
⏱️ 약 25분
SECTION 01 · 실제 질문

1종류를 찾는 if문은 번식한다

"몬스터 A, B, C가 각각 Attack을 구현하면 공격할 때 if문으로 어떤 몬스터인지 계속 찾아야 해. 넌 어떻게 설계할 거야?"

enum class EMonsterType { Slime, Archer, Golem };

void DoAttack(FMonster& M, AActor* Target)
{
    if      (M.Type == EMonsterType::Slime)  { /* 몸통 박치기 */ }
    else if (M.Type == EMonsterType::Archer) { /* 화살 발사 */ }
    else if (M.Type == EMonsterType::Golem)  { /* 광역 내려찍기 */ }
}
// DoMove, OnHit, OnDeath, PlaySound ... 전부 똑같은 if 체인이 생긴다

공격뿐 아니라 이동·피격·사망·사운드까지 같은 분기가 생긴다. 종류 하나를 추가하면 그 분기가 있는 모든 함수를 찾아 고쳐야 하고, 하나라도 빠뜨리면 그 종류만 조용히 아무것도 안 한다(컴파일러도 못 잡는다). 10강 State에서 본 문제와 뿌리가 같다 — "무엇인지 확인하고 분기해서 행동한다"를 "객체에게 그 행동을 시킨다"로 뒤집는 것.

SECTION 02 · 해법 ① 가상 함수

2종류마다 "자기 Attack"을 갖는다

class AMonster
{
public:
    virtual ~AMonster() = default;                 // ★ 반드시 virtual (5절)
    virtual void Attack(AActor* Target) = 0;       // 순수 가상: 자식이 반드시 구현
};
class ASlime  : public AMonster { public: void Attack(AActor* T) override { /* 몸통 박치기 */ } };
class AArcher : public AMonster { public: void Attack(AActor* T) override { /* 화살 발사 */ } };
class AGolem  : public AMonster { public: void Attack(AActor* T) override { /* 광역 내려찍기 */ } };

// 호출하는 쪽 — 종류를 전혀 모른다
for (AMonster* M : Monsters) { M->Attack(Player); }

호출하는 쪽에 if가 하나도 없다. Dragon을 추가하면 새 클래스 하나만 만들면 된다(개방-폐쇄 원칙). 구현을 빠뜨리거나 override 시그니처가 어긋나면 컴파일 에러가 나서 "조용히 아무것도 안 하는" 버그도 막힌다.

Slime 객체         Slime의 vtable                 Archer의 vtable
┌─────────┐       ┌───────────────────────┐    ┌───────────────────────┐
│ vptr ───┼──────→│ Attack → ASlime::Attack  │    │ Attack → AArcher::Attack │
│ HP ...  │       │ ~AMonster → ...          │    │ ~AMonster → ...          │
└─────────┘       └───────────────────────┘    └───────────────────────┘

M->Attack(Player) = ① M의 vptr 읽기  ② vtable의 Attack 칸 읽기  ③ 그 주소로 간접 호출
SECTION 03 · 핵심 · 직접 눌러보기

3디스패치 추적기 — if 체인 vs vtable

몬스터를 눌러 공격시켜보자. 왼쪽은 if 체인이 몇 번 비교하고 나서야 맞는 분기에 도착하는지, 오른쪽은 vptr → vtable → 함수로 곧바로 가는 경로를 보여준다. 뒤쪽 종류(Golem)를 누를수록 if 체인의 비교가 늘어난다.

if / else if 방식

가상 함수 (vtable 디스패치)

if 방식은 종류가 늘수록(그리고 뒤에 있을수록) 비교가 선형으로 늘어난다. 가상 호출은 종류가 몇 개든 포인터 두 번 따라가고 간접 호출 한 번이다. 다만 간접 호출이라 인라인이 안 되고 vtable 접근이 캐시에 없으면 미스가 난다 — 대부분의 게임 로직에선 무시할 수준이지만 수만 개를 매 프레임 도는 핫루프라면 문제가 될 수 있다. 진짜 이득은 속도가 아니라 수정 범위와 누락 방지다. 다음 실험에서 확인한다.

Dragon

위에서 추적기에 Dragon 몬스터가 추가된 것도 확인해보자. 체크를 하나 해제하면 — if 방식은 빌드가 통과한 채로 Dragon만 그 행동을 안 한다(런타임에 발견). 가상 함수는 컴파일 에러다: "추상 클래스는 인스턴스화할 수 없다". 버그를 빌드 시점으로 끌어오는 것이 다형성의 실전 가치다.

SECTION 05 · 실전 함정

5기반 클래스 소멸자는 virtual

AMonster*로 들고 있는 Golem을 delete하면 무슨 일이 일어날까. 소멸자를 virtual로 켜고 끄며 호출 순서를 확인하자.

class AMonster { public: /* virtual */ ~AMonster() {} };
class AGolem : public AMonster { TArray<int32> BigBuffer; };

AMonster* M = new AGolem();
delete M;   // 기반 포인터로 delete
delete를 눌러보자.

virtual이 아니면 표준상 미정의 동작이다(실제로는 대개 기반 소멸자만 호출되어 자식 멤버가 누수). 언리얼의 UObject/AActor는 소멸자가 이미 virtual이고 엔진이 수명을 관리하지만, 순수 C++ 클래스(F 접두사)에서 상속을 쓸 때는 직접 챙겨야 한다. 또 하나: 컨테이너에 TArray<AMonster>처럼 값으로 저장하면 슬라이싱이 일어나 자식 부분이 잘리고 다형성이 사라진다 — 다형성은 포인터/참조로만 동작한다.

SECTION 06 · 판단

6무엇이 다른가에 따라 고른다

몬스터끼리 다른 것선택이유
수치 (데미지·사거리·쿨다운)데이터 테이블(UDataTable/UDataAsset)클래스를 나눌 필요 없음. 새 몬스터 = 행 추가
행동 자체 몇 종류가상 함수가장 단순. 호출부에 if가 없다
행동이 조합되거나 런타임에 교체컴포지션(Strategy) / 컴포넌트상속 트리가 다중 상속의 늪이 되는 걸 피함
상태에 따라 행동이 바뀜State Pattern (10강)현재 상태 객체에게 위임, 전환 조건은 상태가 앎
// Strategy — 행동을 별도 객체로 빼서 몬스터가 갖게 한다 (10강 State와 뼈대가 같다)
class IAttackBehavior { public: virtual ~IAttackBehavior() = default; virtual void Execute(AMonster* Owner, AActor* Target) = 0; };

class AMonster
{
public:
    void Attack(AActor* Target) { AttackBehavior->Execute(this, Target); }                 // 위임
    void SetAttack(TUniquePtr<IAttackBehavior> B) { AttackBehavior = MoveTemp(B); }   // 런타임 교체
private:
    TUniquePtr<IAttackBehavior> AttackBehavior;
};

State와의 차이: State는 상태가 바뀌며 스스로 전환하고, Strategy는 바깥에서 정책을 주입한다. 보스가 페이즈 2에서 공격 방식이 바뀌면 State에 가깝고, 몬스터 프리셋마다 공격 방식을 조립하면 Strategy에 가깝다. 몬스터가 수만 개라면 종류별로 배열을 나눠 일괄 처리하는 데이터 지향 방식도 있지만, 일반적인 게임 로직에선 가상 함수로 충분하다.
