static의 여러 얼굴

static은 붙는 위치에 따라 완전히 다른 일을 한다. 총알 카운터를 직접 만들어보고, static 멤버 함수에 왜 this가 없는지 컴파일러 관점까지 뜯어본다.

🧩 네 가지 얼굴
📌 선수지식 없음
⏱️ 약 20분
SECTION 01 · 버그

1총알 몇 발 쐈는지 세다가 만난 버그

FPS 게임에서 "지금까지 발사된 총알 총개수"를 디버그 UI에 띄우고 싶다. 총알 클래스에 카운터를 하나 넣었다.

class ABullet : public AActor
{
public:
    int32 FiredCount = 0;   // 총알 하나에 카운터 하나...?

    ABullet() { FiredCount++; }
};

총알을 100발 쏘고 아무 총알이나 하나 골라 FiredCount를 찍어보면 1이 나온다. 각 총알은 자기가 태어날 때 자기 카운터만 1로 만들 뿐이다. "전체" 개수를 세려면 모든 인스턴스가 공유하는 변수가 필요하다 — static 하나면 해결된다.

SECTION 02 · 지도

2static의 네 얼굴

static은 어디에 붙느냐에 따라 완전히 다른 의미가 된다. 공통점은 "인스턴스/함수 호출과 무관하게, 한 곳에 고정되어 산다"는 성격이다.

지역 static 변수

딱 한 번만 초기화되고, 함수가 끝나도 값이 유지된다

파일 스코프 (내부 링키지)

이 .cpp 파일 밖에서는 안 보인다

static 멤버 변수

인스턴스마다 따로 있지 않고, 클래스 전체가 하나를 공유

static 멤버 함수

특정 인스턴스에 속하지 않는다. this가 없다

지역 static — "딱 한 번만"

void PrintCallCount()
{
    static int32 CallCount = 0;   // 최초 호출 때 딱 한 번만 초기화
    CallCount++;
    UE_LOG(LogTemp, Log, TEXT("%d번째 호출됨"), CallCount);
}
// 1번째 → 2번째 → 3번째 ... CallCount가 0으로 안 돌아감

C++11부터 지역 static 변수의 최초 초기화는 스레드 안전하게 보장된다. 하지만 초기화된 값을 여러 스레드가 동시에 읽고 쓰는 것까지 안전한 건 아니다.

파일 스코프 static — "이 파일 안에서만 보여"

// BulletUtils.cpp
static float CalculateFalloff(float Distance) { ... }
// 다른 .cpp에서 쓰려 하면 링커 에러 — 내부 링키지라 이름이 파일 밖에 안 보임

static이 없으면 외부 링키지(다른 파일에서 extern으로 가져다 씀), 있으면 내부 링키지(이 번역 단위 안에서만 존재). 요즘은 익명 네임스페이스를 더 권장하지만 기존 코드에서 흔히 본다.

SECTION 03 · 핵심 · 직접 만들어보기

3static 멤버 변수 — "이 클래스는 하나만 가진다"

토글로 "일반 멤버 변수"와 "static 멤버 변수"를 바꿔가며 총알을 생성해보자. 공유되는 것과 안 되는 것의 차이가 눈에 보인다.

일반 멤버 변수
static 멤버 변수
ABullet::FiredCount (클래스 전체 공유)
0
각 총알의 FiredCount가 전부 1이다. "총 몇 발 쐈나"를 알려면 이 카드를 전부 더해야 한다 — 도입의 버그가 이거다.
class ABullet : public AActor
{
public:
    static int32 FiredCount;   // 선언만. 실체(정의)는 밖에서 한 번.
    ABullet() { FiredCount++; }
};
// .cpp 파일에서 딱 한 번 정의(메모리 실체를 만들어줌)
int32 ABullet::FiredCount = 0;

클래스 안의 선언은 실체 없는 선언일 뿐이다. 정의를 빼먹으면 링크 단계에서 undefined reference 에러가 난다 (C++17 inline static은 예외 — 헤더 한 줄로 끝).

SECTION 04 · 면접 핵심

4static 멤버 함수 — 왜 this가 없나

일반 멤버 함수는 숨겨진 첫 번째 매개변수로 this를 받는 일반 함수다. 버튼을 눌러 컴파일러가 실제로 만드는 모양을 확인해보자.

static 멤버 함수는 사실상 "클래스라는 이름공간 안에 들어 있는 평범한 전역 함수"다. 그래서 (1) 인스턴스 없이 호출 가능, (2) non-static 멤버에 직접 접근 불가, (3) const 멤버 함수가 될 수 없다.

SECTION 05 · 조합

5static과 const — 완전히 다른 두 축

키워드답하는 질문관련 축
static이 변수가 어디에, 몇 개 존재하는가존재 방식 (생명주기·저장 위치)
const이 변수의 값을 바꿀 수 있는가불변성
int32 A = 10;                 // 매번 새로 생성, 값도 바꿀 수 있음
const int32 B = 10;           // 매번 새로 생성되지만, 값은 못 바꿈
static int32 C = 10;          // 딱 한 번만 초기화, 값 유지 + 바꿀 수 있음
static const int32 D = 10;    // 딱 한 번만 초기화 + 절대 못 바꿈 — 진짜 상수

몬스터 최대 체력처럼 공유되면서 값도 안 바뀌어야 하는 게임 밸런스 상수는 static constexpr가 정석이다 (C++17부터 암묵적 inline이라 .cpp 정의도 불필요).

SECTION 06 · 내부 동작

6static은 메모리 어디에 사는가

힙도 스택도 아니다. static은 컴파일 시점에 이미 자리가 정해지는 데이터/코드 영역에 산다.

코드(텍스트) 영역static 멤버 함수 — 애초에 변수가 아니라 명령어라 저장 개념 자체가 없음
데이터 영역 (+BSS)지역 static 변수 · 파일 스코프 static · static 멤버 변수 — 프로그램 로드 시 이미 자리 잡음
힙 (Heap)new로 런타임에 그때그때 요청 — AActor/UObject가 사는 곳, GC 대상
스택 (Stack)함수 호출될 때 생겼다 리턴하면 사라짐 — 일반 지역 변수

static은 GC 대상이 아니고, 어떤 인스턴스가 몇 개 살아있든 상관없이 프로그램 종료까지 그 자리에 그대로 있다.
