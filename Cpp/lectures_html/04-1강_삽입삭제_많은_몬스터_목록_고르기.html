몬스터 목록, 뭘 쓸까

"매 프레임 전체를 순회하는데 삽입/삭제도 많다." 반사적으로 std::list라고 답하면 4강의 함정에 그대로 빠진다. 후보를 걸러내고, swap-and-pop과 지연 삭제로 푸는 과정을 직접 눌러보며 익힌다.

SECTION 01 · 실제 질문

1"몬스터 목록에 어떤 STL 자료구조를 쓸래?"

"게임에서 몬스터 객체의 목록을 만들어야 해. 매 프레임마다 호출해서 렌더해야 하고, 삽입과 삭제가 많이 일어나." — 조건이 두 개다.

❌ 반사적인 답

"삽입/삭제가 많으니까 std::list요." — 조건 ①(매 프레임 전체 순회)을 안 봤다. 순회가 노드마다 캐시 미스를 낸다(4강).

✅ 조건을 먼저 나눈다

① 접근 패턴이 매 프레임 전체 순회 → 연속 메모리 우선. ② 삭제는 순서가 필요한가? → 아니면 swap-and-pop. 이 순서로 골라야 한다.

SECTION 02 · 후보 걸러내기

2후보를 늘어놓고, 조건 ①로 걸러낸다

STL언리얼순회중간 삭제비고
vectorTArray매우 빠름O(n) → swap-and-pop이면 O(1)기본값
listTDoubleLinkedList느림(노드마다 미스)반복자 있으면 O(1)주소·반복자 안정
dequeTDeque (UE5)vector보다 조금 느림O(n)앞/뒤 삽입이 필요할 때
set / mapTSet / TMap느림O(log n) / O(1) 평균키로 찾을 때

전 원소 순회가 가장 잦은 연산이면 연속 메모리가 아닌 후보는 대부분 탈락한다. 남는 문제는 단 하나 — "vector의 중간 삭제가 O(n)인데 어떡하나." 답은 swap-and-pop이다.

// 순서가 상관없으면: 지울 자리에 마지막 원소를 옮기고 끝을 제거 — O(1)
void RemoveAtSwap(std::vector<FMonster>& V, size_t Index)
{
    V[Index] = std::move(V.back());
    V.pop_back();
}
// 언리얼은 이미 만들어 놨다
Monsters.RemoveAtSwap(Index);
SECTION 03 · 핵심 · 직접 지워보기

3몬스터 목록 삭제 시뮬레이터

전략을 고르고 몬스터 카드를 클릭해 죽여보자. 노란 카드는 이번에 메모리에서 옮겨진 원소다. 전략마다 원소 이동 횟수와 순서 유지 여부가 어떻게 달라지는지 본다. 순서 유지가 필요 없다면 왜 swap-and-pop이 이기는지가 보인다.

카드를 눌러 몬스터를 죽여보자.

해볼 것 ① vector erase로 앞쪽(#0 근처)을 죽이면 뒤 원소가 전부 한 칸씩 밀린다(노란색). ② swap-and-pop은 이동이 1번뿐이지만 ID 순서가 뒤섞인다 — 몬스터 목록에선 순서가 의미 없으니 괜찮다. ③ 지연 삭제는 죽이는 순간엔 이동이 0이고 표시만 한다 → "프레임 끝 정리"에서 한 번에 처리. ④ list는 이동이 없다(포인터 2개만 수정). 그런데 이건 그 노드를 이미 들고 있을 때의 이야기다 — 아래 계산기에서 "찾아가는 비용"을 넣어보자.

SECTION 04 · 핵심 · 프레임 비용

4한 프레임에 얼마가 드나 — 순회가 지배한다

몬스터 N마리를 매 프레임 순회하고, 그 프레임에 K마리가 죽고 K마리가 스폰된다고 하자. 슬라이더를 움직여 전략별 비용을 비교한다. 삭제를 O(1)로 만들어도 순회 비용이 크면 list가 지는 이유를 확인하는 게 목표다.

몬스터 수 N5000
프레임당 죽는 수 K20
list 노드 순회 비용 배수8(캐시 미스 가중치)

교육용 단순 모델이다. 원소 순회 1개 = 1, 연속 메모리 원소 이동 1개 = 0.25(순차 복사라 더 쌈), list 노드 순회 1개 = 위의 배수, list 스폰(new) 1회 = 20. 실제 수치는 CPU·할당기마다 다르지만 자릿수 감각은 4강의 캐시 미스 표와 같다. list의 "찾아가는" 삭제는 평균 N/2개 노드를 따라간다.

SECTION 05 · 실전 함정

5순회 중 삭제 — 가장 자주 터지는 버그

몬스터가 죽는 일은 대개 순회 도중에 일어난다. 아래는 죽은 몬스터 3마리(✕)가 섞인 목록에서 세 가지 방식으로 정리한 결과다.

// ❌ 순회 중 삭제 — 반복자 무효화 / 원소 건너뜀 / 크래시
for (AMonster* M : Monsters) { if (M->IsDead()) Monsters.Remove(M); }

// ✅ ① 역순 인덱스 + swap  ② 지연 삭제(프레임 끝에 한 번에)
for (int32 i = Monsters.Num() - 1; i >= 0; --i) { if (Monsters[i]->IsDead()) Monsters.RemoveAtSwap(i); }
Monsters.RemoveAll([](const AMonster* M){ return M->IsDead(); });   // C++20: std::erase_if

삽입도 마찬가지다. 순회 중 스폰이 일어나 push_back으로 재할당이 일어나면 순회 중인 반복자와 원소를 가리키던 모든 포인터가 무효화된다. 새로 생긴 건 PendingAdd에 모아뒀다가 순회 뒤에 합친다. 밖에서 포인터를 들고 있다면 Reserve / 포인터 저장 / 핸들(인덱스+세대) / Object Pool(7강) 중 하나가 필요하다.
