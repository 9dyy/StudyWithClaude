내가 짠 .exe가 실행되면 변수들은 메모리 어디에 살까? 코드 한 줄씩 클릭하며 Text·Data·BSS·Heap·Stack을 직접 짚어본다.

SECTION 01 · 시작

1.exe 더블클릭하면 무슨 일이?

디스크의 정적인 바이트(.exe)가 메모리에 올라와 도는 실체가 프로세스다. OS가 메모리에 영역을 잡고 코드·데이터를 배치한 뒤 main()으로 점프한다.

.exe 파일 = 디스크의 정적 바이트  →  프로세스 = 메모리에서 도는 실체

그 프로세스의 메모리는 5개 영역으로 나뉜다. 아래에서 어떤 변수가 어디 사는지 직접 짚어보자. ↓

SECTION 04 · 슬라이더 실험

4스택 오버플로를 만들어보기

함수를 호출할 때마다 스택 프레임이 쌓인다. 재귀 깊이를 늘려 스택 한도를 넘겨보자.

재귀 호출 깊이5
스택 한도 (1~8MB)

스택 오버플로의 두 원인: ① 재귀가 너무 깊음, ② 함수 안에 너무 큰 지역 배열(FVertex v[100000]). 큰 데이터는 Heap(TArray·new)에 잡아야 한다.

SECTION 05 · 격리와 공유

5같은 exe를 2번 띄우면?

각자 독립된 주소 공간을 갖는다. Stack·Heap·Data·BSS는 따로지만, 읽기 전용인 Text(코드)는 OS가 물리적으로 공유시켜 RAM을 아낀다.

🎮 프로세스 A (MyGame.exe)

Stack — A 것
Heap — A 것
BSS/Data — A 것
Text — 공유 ♻

🎮 프로세스 B (같은 exe)

Stack — B 것
Heap — B 것
BSS/Data — B 것
Text — 공유 ♻

A의 전역변수 변경은 B에 안 보인다(다른 주소 공간). 단, 스레드는 다르다 — 같은 프로세스의 스레드들은 Heap·Data를 공유한다(4강).
