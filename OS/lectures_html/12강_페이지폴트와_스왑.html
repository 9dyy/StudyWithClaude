페이지 폴트와 스왑

CPU도 GPU도 한가하고 메모리도 남는데, 게임이 갑자기 0.5초 멈춘다. 범인은 누구일까? 직접 시뮬레이션하며 추적한다.

SECTION 02 · 비교 실험

2Minor Fault vs Major Fault

페이지 폴트는 에러가 아니라 정상 동작이다. 다만 디스크를 건드리느냐가 운명을 가른다. 두 버튼을 눌러 처리 시간을 비교해보자.

● Minor Fault (소프트)

페이지가 이미 RAM 어딘가에 있음. 페이지 테이블만 고치면 끝. (demand paging 첫 접근, 공유 라이브러리 등)

— μs

● Major Fault (하드)

데이터가 디스크에 있어 읽어와야 함. SSD라도 RAM보다 수백~수천 배 느리다. (스왑된 페이지, 에셋 스트리밍)

— ms
같은 "페이지 폴트"라도 처리 비용은 약 1000배 차이. 게임 hitch의 주범은 Major Fault.

SECTION 04 · 슬라이더 실험

4스래싱 — 워킹셋이 RAM을 넘으면

워킹셋(현재 활발히 쓰는 페이지 집합)이 물리 RAM보다 커지면, 페이지를 내리자마자 또 필요해서 디스크만 두드린다. 슬라이더로 메모리 압력을 올려보자.

메모리 압력 (실행 중인 작업량)낮음
물리 RAM 한계

CPU는 노는데 디스크만 100% — 시스템 전체가 먹통이 되는 그 느낌. 콘솔(PS5·Xbox)은 스왑이 거의 없어 한계를 넘으면 스왑 대신 OOM 크래시. 그래서 메모리 예산이 PC보다 빡세다.

SECTION 05 · 실무

5게임 개발자는 hitch를 어떻게 잡나

🔥

Pre-touch 워밍업

로딩 화면에서 필요한 페이지를 미리 한 번 건드려 RAM에 올려둔다. 게임플레이 중 Major Fault 방지.

🧵

비동기 스트리밍

디스크 대기를 워커 스레드로 넘겨 Game Thread는 안 멈춘다. (15강 비동기 I/O)

💰
