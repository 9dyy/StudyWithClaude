데드락 (Deadlock)

락 두 개를 엇갈리게 잡으면 게임이 영원히 멈춘다. 크래시도 없이. 직접 교착을 만들어보고, 토글 하나로 풀어본다.

🔒 순환 대기 = 교착
🧩 선수지식 8강
⏱️ 약 20분
SECTION 01 · 증상

1게임이 멈췄다 — 크래시도 아닌데

새 인벤토리 시스템에서 가끔 게임이 영구히 정지한다. CPU 0%, 크래시 로그 없음. 코드를 보자.

void Equip(...)   {  FScopeLock A(&InventoryLock);  FScopeLock B(&EquipLock);  ... }
void Unequip(...) {  FScopeLock A(&EquipLock);      FScopeLock B(&InventoryLock); ... }
                                     ↑ 락 잡는 순서가 정반대!

스레드 A가 Equip, 스레드 B가 동시에 Unequip을 호출하면? 아래에서 직접 돌려보자. ↓

SECTION 02 · 핵심 · 교착 재현기

2데드락을 만들고, 풀어보기

두 스레드가 락 2개를 잡으려 한다. 토글을 끄면 서로 반대 순서로 잡아 교착, 켜면 둘 다 같은 순서로 잡아 안전하다.

위험 모드에서 A는 Inventory를 잡고 Equip을 기다리고, B는 Equip을 잡고 Inventory를 기다린다 → 순환 대기. 아무도 양보 안 해서 영원히 멈춘다.

SECTION 03 · 면접 필수 암기

3데드락의 4가지 조건 (Coffman)

네 개가 다 만족돼야 데드락이 가능하다. 하나라도 깨면 데드락은 없다. 카드를 눌러 설명을 펼쳐보자.

→ 해결 전략은 이 중 하나를 못 만들게 막는 것. 보통 4번(순환 대기)을 깬다.

SECTION 04 · 대처법

4해결 전략 4가지

🛡️

예방 — 락 순서 고정실무 표준

락에 전역 순서를 정하고 모든 코드가 그 순서대로 잡는다. 순환 대기가 생길 수 없다. 위 시뮬의 "안전" 모드가 이것.

🏦

회피 — Banker's Algorithm

요청마다 "허락하면 데드락 날까?" 미리 분석. 모든 미래 요청을 알아야 해서 실무에선 거의 안 씀. 이름만 알면 됨.

🔍

탐지 후 복구

일단 나게 두고 주기적으로 자원 그래프에서 사이클을 찾아 한 스레드를 강제 종료/롤백. DB 트랜잭션이 이 방식.

🙈

무시 — 타조 알고리즘

"날 일 거의 없으니 신경 안 씀." 유닉스 일부가 이렇게. 게임 클라는 멈춤=환불이라 무시 불가.

SECTION 05 · 구분

5데드락의 친척들

Livelock

서로 양보만 반복해 멈추진 않지만 진척이 없는 상태. try-lock 남용 시.

Starvation (기아)

우선순위에 밀려 특정 스레드가 영원히 자원을 못 받음. Aging(오래 기다리면 우선순위↑)으로 해결.

Priority Inversion

낮은 우선순위가 락을 쥐어 높은 우선순위가 못 돔. Priority Inheritance로 해결 (6강).
