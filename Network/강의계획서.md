# 네트워크 강의 계획서

> **수강생:** 언리얼 C++ 클라이언트 개발 신입 (네트워크 한 번 배웠지만 휘발됨)
> **목표:** 이직 면접에서 "멀티플레이 좀 아는 클라 개발자"로 보일 수준까지.
> **분량:** 본강 15강 + 보너스 1강

---

## 이 강의가 지향하는 것

대학교 네트워크 교재처럼 "OSI 7계층을 순서대로 쓰시오" 를 외우는 강의가 아니다.
**언리얼 C++로 멀티플레이 게임을 만드는 사람이 실제로 겪는 상황**과 네트워크 개념을 1:1로 붙여서 설명한다.

예시:
- "왜 FPS는 UDP를 쓰고 거래소는 TCP를 쓰지?" → 전송 계층 신뢰성 트레이드오프
- "패킷을 한 번에 보냈는데 왜 두 번에 나눠서 도착하지?" → TCP 스트림, 패킷 경계 문제
- "핑이 30인데 왜 총 맞은 판정이 이상하지?" → RTT, 지연 보상, 클라 예측
- "내가 보낸 캐릭터 위치가 왜 다른 플레이어한텐 늦게 보이지?" → 언리얼 Replication

각 강의는 **"이걸 모르면 면접에서 답 못하는 것"** 과 **"이걸 모르면 멀티플레이 짤 때 헛발질하는 것"** 을 모두 다룬다.

## 학습 방식

- 각 강의는 별도 `.md` 파일로 `lectures/` 폴더에 둔다.
- 모든 코드 예제는 **C++ 표준 또는 언리얼 API**로 작성한다. (Python, Java X)
- 강의 끝에는 **면접 질문 5개 이상**과 **간단한 셀프 체크**를 둔다.
- 한 강의 분량: 읽는 데 15~25분.

## 커리큘럼 (총 15강 + 보너스)

### Part 1. 네트워크 기초 — "패킷이 게임에 도착하기까지"

| 강의 | 제목 | 핵심 키워드 |
|------|------|------------|
| 1강 | 네트워크란 무엇인가 | 왜 멀티플레이는 어려운가, OSI 7계층 vs TCP/IP 4계층, 캡슐화 |
| 2강 | IP 주소와 라우팅 | IPv4/IPv6, 서브넷, 공인/사설 IP, NAT, 매치메이킹에서 상대 IP를 못 받는 이유 |
| 3강 | 포트와 소켓 | 포트 번호, 소켓 = IP + 포트, well-known 포트, 한 서버가 수천 명을 받는 원리 |

### Part 2. 전송 계층 — "면접에서 가장 많이 물어보는 곳"

| 강의 | 제목 | 핵심 키워드 |
|------|------|------------|
| 4강 | TCP — 신뢰성의 대가 | 연결 지향, 3-way / 4-way handshake, 시퀀스 번호, ACK, 재전송 |
| 5강 | UDP — 빠름의 대가 | 비연결, 작은 헤더, 패킷 유실/순서 뒤바뀜, FPS가 UDP 쓰는 이유 |
| 6강 | TCP vs UDP, 게임은 뭘 쓰나 | 선택 기준, 장르별 선택, 신뢰성 UDP(Reliable UDP)라는 절충 |
| 7강 | 흐름 제어·혼잡 제어와 Nagle | 슬라이딩 윈도우, 혼잡 제어, Nagle 알고리즘과 `TCP_NODELAY`(게임이 끄는 이유) |

### Part 3. 소켓 프로그래밍 — "직접 짜봐야 이해됨"

| 강의 | 제목 | 핵심 키워드 |
|------|------|------------|
| 8강 | 소켓 프로그래밍 기초 | Berkeley socket / Winsock, `socket`/`bind`/`listen`/`accept`/`connect` |
| 9강 | 블로킹·논블로킹과 I/O 멀티플렉싱 | `select`, IOCP, 한 스레드로 수천 연결 받기, 언리얼 `FSocket` |
| 10강 | 패킷 설계와 직렬화 | 패킷 헤더 구조, 엔디안, 바이트 정렬, TCP 경계 문제(부분 수신/합쳐짐) |

> **Part 3 깊이:** 클라 면접 선까지만. `socket()`을 직접 처음부터 짜는 서버 구현이 아니라, "어떤 함수가 무슨 일을 하고 왜 필요한가"를 코드로 읽고 이해하는 수준. IOCP·고성능 서버 내부는 한 줄 소개로 끝낸다.

### Part 4. 애플리케이션 계층 — "로그인·상점·랭킹은 여기"

| 강의 | 제목 | 핵심 키워드 |
|------|------|------------|
| 11강 | HTTP / HTTPS | 요청/응답, 메서드, 상태 코드, REST, 게임 로그인·랭킹 API, 언리얼 `FHttpModule` |
| 12강 | DNS | 도메인 → IP, 리졸빙 과정, 캐싱, 접속 서버 주소가 도메인인 이유 |
| 13강 | TLS와 게임 보안 | 대칭/비대칭 암호화, TLS 핸드셰이크, 패킷 변조·치팅과 서버 권한 검증 |

### Part 5. 게임 네트워킹 — "언리얼 멀티플레이의 정체"

| 강의 | 제목 | 핵심 키워드 |

## 참고: 이 강의가 "다루지 않는" 것

이직 면접 + 클라 개발자 일상에 거의 안 나오는 주제는 의도적으로 뺐다.

- 물리 계층 디테일 (전압, 변조 방식, 케이블 규격) — 면접에 거의 안 나옴
- 라우팅 프로토콜 내부 (OSPF, BGP 알고리즘) — 인프라/서버 직군 범위
- 통신 이론 (샤논 정리, 오류 정정 코드) — 학술 범위
- 대규모 분산 서버 아키텍처 (샤딩, 로드밸런싱 디테일) — 서버 직군 면접 범위. 필요하면 보너스에서 한 줄

원한다면 추가/제외 가능. 알려주면 반영한다.
