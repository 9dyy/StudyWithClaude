소켓 프로그래밍 기초

언리얼 클라 개발자가 socket()을 직접 부를 일은 드물다. 그래도 면접관은 묻는다 — "서버랑 클라가 각각 어떤 함수를 어떤 순서로 호출하나요?" 서버와 클라를 직접 조작하며 그 흐름을 손에 익힌다.

🔌 서버는 bind→listen→accept, 클라는 connect
🧩 선수지식 3강 · 4강
⏱️ 약 20분
SECTION 01 · 도입

1엔진이 다 해주는데 이걸 왜 배우나

언리얼에선 Replication이 다 해준다. 그런데 면접관은 이렇게 묻는다.

"소켓 통신 흐름을 설명해보세요. 서버랑 클라이언트가 각각 어떤 함수를 호출하나요?"

이걸 못 답하면 "네트워크 안다"고 말하기 어렵다. 목표는 직접 서버를 구현하는 게 아니라 흐름을 그릴 수 있는 것이다.

소켓 API의 뿌리: 1980년대 유닉스의 Berkeley Socket(BSD 소켓). 리눅스/맥은 거의 그대로, 윈도우는 Winsock(WSAStartup()으로 초기화, closesocket()으로 닫는 등 약간 다름). 언리얼 FSocket은 이걸 플랫폼별로 감싼 추상화다.

SECTION 02 · 개념

2함수 7개 — 이게 전부다

함수하는 일누가
socket()소켓 하나 생성서버·클라 둘 다
bind()소켓에 IP·포트 묶기서버 (듣는 주소 고정)
listen()"연결 받을 준비 됨" 표시서버
accept()들어온 연결 수락, 연결 소켓 반환서버
connect()서버로 연결 시도 (handshake)클라
send() / recv()데이터 보내기 / 받기서버·클라 둘 다
close()소켓 닫기 (자원 반납)서버·클라 둘 다
       서버                                클라이언트
        │                                     │
   socket()   소켓 생성                    socket()   소켓 생성
        │                                     │
   bind()     "나 7777번 포트 쓸게"            │
        │                                     │
   listen()   "연결 받을 준비 됨"              │
        │                                     │
   accept()   ←──── 연결 대기 ────       connect()   "연결하자"
        │     ← ─ ─ 3-way handshake ─ ─ →     │   (SYN/SYN+ACK/ACK)
   (연결 소켓                                  │
    하나 생김) ────── 연결 성립 ──────────────  │
        │                                     │
   recv()/send() ←──── 데이터 교환 ────→  send()/recv()
        │                                     │
   close()    연결 종료                     close()

서버는 bind → listen → accept(받는 쪽 준비), 클라는 connect 하나(거는 쪽). 그리고 accept()가 반환하는 건 새 연결 소켓이다 — 이 비대칭이 핵심. 아래에서 직접 확인한다.

SECTION 03 · 핵심 · 직접 돌려보기

3소켓 호출 시뮬레이터 — 순서를 틀리면 어떻게 되나

서버와 클라 함수 버튼을 마음대로 눌러보자. 정석 순서는 물론이고, 순서를 틀렸을 때 무슨 일이 생기는지가 이 위젯의 핵심이다. (예: listen 전에 connect / accept를 안 했는데 연결은? / 대기열이 차면?) 서버는 listen(3) — 대기열 3칸.

🖥️ 서버 포트 7777

💻 클라이언트들 최대 6명

해볼 것 ① 서버 준비 전에 connect() → 거부(RST). ② bind 없이 listen() → 막힌다. ③ 서버 준비 후 클라 3명 connect() → accept()를 안 했는데도 연결은 이미 성립해 대기열에 들어가 있다. ④ 대기열이 찬 상태에서 4번째 connect() → 밀려난다. ⑤ accept()를 누를 때마다 연결 소켓이 새로 생기고, listen 소켓은 그대로다. ⑥ 대기열이 빈데 accept() → 블로킹(9강의 문제).

SECTION 04 · 코드

4언리얼 FSocket으로 — 클라이언트와 서버

클라가 제일 단순하다. socket → connect → send/recv → close.

ISocketSubsystem* SocketSub = ISocketSubsystem::Get(PLATFORM_SOCKETSUBSYSTEM);

// 1) socket() — TCP 소켓 생성
FSocket* Socket = SocketSub->CreateSocket(NAME_Stream, TEXT("Client"), false);

// 2) 서버 주소 구성 (IP + 포트)
TSharedRef<FInternetAddr> ServerAddr = SocketSub->CreateInternetAddr();
bool bValid;
ServerAddr->SetIp(TEXT("203.0.113.10"), bValid);
ServerAddr->SetPort(7777);

// 3) connect() — 내부적으로 3-way handshake 발생
if (Socket->Connect(*ServerAddr))
{
    // 4) send() — 데이터 보내기
    FString Msg = TEXT("Login:Koo");
    int32 Sent = 0;
    Socket->Send((uint8*)TCHAR_TO_UTF8(*Msg), Msg.Len(), Sent);

    // 5) recv() — 응답 받기
    uint8 Buffer[1024]; int32 Read = 0;
    if (Socket->Recv(Buffer, sizeof(Buffer), Read)) { /* 처리 */ }
}

// 6) close() — 자원 반납 (3강에서 강조한 것)
Socket->Close();
SocketSub->DestroySocket(Socket);

서버는 socket → bind → listen → accept → recv/send → close. 직접 짤 일은 드물지만 읽을 줄은 알아야 한다.

FSocket* ListenSocket = SocketSub->CreateSocket(NAME_Stream, TEXT("Server"), false);   // 1) socket()

TSharedRef<FInternetAddr> BindAddr = SocketSub->CreateInternetAddr();
BindAddr->SetAnyAddress();      // 모든 인터페이스에서
BindAddr->SetPort(7777);
ListenSocket->Bind(*BindAddr);  // 2) bind() — "나 7777번 포트로 들을게"

ListenSocket->Listen(8);        // 3) listen() — 연결 대기열 준비 (인자 = 대기 큐 크기)

bool bPending = false;
if (ListenSocket->HasPendingConnection(bPending) && bPending)
{
    // 4) accept() — 들어온 연결을 수락, "연결 소켓"을 새로 반환
    FSocket* ClientSocket = ListenSocket->Accept(TEXT("ClientConn"));
    //       ↑ 이 소켓으로 이 클라와 통신. ListenSocket은 계속 새 연결을 받음

    uint8 Buffer[1024]; int32 Read = 0;
    ClientSocket->Recv(Buffer, sizeof(Buffer), Read);   // 5) recv()/send()

    ClientSocket->Close();                                // 6) close()
    SocketSub->DestroySocket(ClientSocket);
}

면접용 비유: listen 소켓은 문 앞에서 손님을 맞는 직원, accept가 만든 연결 소켓은 그 손님 전담 직원이다. 손님(클라)마다 전담 소켓이 생기니 동시에 여럿을 처리할 수 있다(3강의 4-tuple).

SECTION 05 · 함정

5손님 한 명 받는 동안 다른 손님은?

위 서버 코드엔 함정이 있다. accept()로 한 명을 받아 recv()로 그 사람 데이터를 기다리는 동안 다른 클라는 접속을 못 한다. recv()가 데이터 올 때까지 멈춰 있기(블로킹) 때문이다. (시뮬레이터에서 대기열이 빈 채 accept()를 눌렀을 때 나온 그 메시지다.)

손님 100명을 동시에 받으려면 —

① 블로킹을 안 쓴다

논블로킹 소켓

② 한 스레드로 여러 소켓 감시

select, IOCP

③ 연결마다 스레드

수백 명까진 OK

게임 서버가 수천 명을 받는 비밀이 거기 있다. 이 강의는 "함수 흐름"까지, 동시 처리는 9강에서 본다.
