UDP, 빠름의 대가

신뢰성을 버리고 속도를 택한 UDP가 왜 FPS의 선택인가. 그리고 "막 유실돼도 되나?"에 대한 답 — 필요한 것만 골라 신뢰성을 얹는 방식을 직접 실험한다.

📮 던지고 신경 안 쓴다
🧩 선수지식 4강
⏱️ 약 15분
SECTION 01 · 도입

1TCP로 FPS를 만들면 생기는 일

4강 문제를 다시 보자. 내 캐릭터 위치를 TCP로 1초에 60번 보내는데 중간에 패킷 하나가 유실된다.

위치1(0ms) → 위치2(16ms) 유실! → 위치3(32ms) 도착 but 대기 → 위치4(48ms) 도착 but 대기
                  └ TCP: "위치2 재전송될 때까지 위치3,4 못 줘" (순서 보장 때문)

내 화면: 캐릭터가 16ms 지점에서 멈춤 → 위치2 재전송 도착 → 갑자기 48ms로 순간이동

잘 생각해보자. 위치2는 이미 쓸모없다. 32ms, 48ms 위치가 이미 와 있는데 굳이 16ms 전 위치를 기다릴 이유가 없다. TCP는 "다 도착해야 하고 순서대로여야 한다"는 신념 때문에 이걸 못 한다. 그래서 다른 도구가 필요하다 — UDP.

SECTION 02 · 철학

2"일단 던지고 신경 안 쓴다"

UDP는 TCP와 정반대다. 그냥 보낸다. 도착 여부는 신경 안 쓴다. 데이터를 서로 모르는 독립 덩어리(데이터그램)로 던진다.

TCPUDP
연결맺음 (handshake)안 맺음
신뢰성보장 (재전송)보장 안 함 (유실돼도 끝)
순서보장보장 안 함
속도느림빠름
헤더 크기20바이트+8바이트

📬 TCP = 등기우편

받았다는 사인을 받고, 안 오면 다시 보낸다. 느리지만 확실.

📄 UDP = 전단지 뿌리기

그냥 뿌린다. 몇 장이 날아가도 신경 안 쓴다. 빠르다.

UDP 헤더 (8바이트)
┌────────────┬────────────┬────────┬────────┐
│ 출발지포트 │ 목적지포트 │  길이  │ 체크섬 │
└────────────┴────────────┴────────┴────────┘
신뢰성 관련 필드가 아예 없다 = 가볍고 빠르다
SECTION 03 · 게임과의 궁합

3실시간 게임은 "최신성 > 완전성"

위치1 → 위치2 유실 → 위치3 도착(바로 표시) → 위치4 도착(바로 표시)
              └ 그냥 버림. 어차피 위치3이 더 최신이라 상관없음

내 화면: 위치2만 살짝 건너뛰고 위치3,4로 부드럽게 진행 (멈춤 없음)

0.1초 전 위치를 정확히 받느니 지금 위치를 대충 받는 게 낫다. FPS·레이싱·액션이 위치/입력 동기화에 UDP를 쓰는 이유 — 유실을 감수하는 대신 지연을 없앤다.

SECTION 04 · 핵심 · 직접 돌려보기

4"그럼 막 유실돼도 되나?" — 신뢰성을 어디에 얹을까

매 틱 위치 패킷을 보내고 8틱마다 "플레이어 사망" 이벤트도 보낸다. 유실률을 바꿔가며 세 전략을 비교해보자. 초록이 가장 좋은 값, 빨강이 가장 나쁜 값이다.

패킷 유실률 20%

전제: 편도 2틱, 재전송 타임아웃 6틱, 300틱 × 8회 평균. ① 유실률 20~30%에서 순수 UDP는 이벤트가 그만큼 사라진다. ② 신뢰성 UDP는 이벤트만 ACK/재전송해서 100% 도착, 위치는 그대로 매끈하다. ③ TCP처럼 전부 신뢰성+순서로 하면 이벤트는 되지만 화면 정지가 확 늘고 트래픽도 커진다. → "필요한 것만 골라서 신뢰성"이 게임의 답이다.

SECTION 05 · 코드

5언리얼 UDP 소켓 — Connect()가 없다

// NAME_DGram = UDP. (TCP는 NAME_Stream)
FSocket* UdpSocket = ISocketSubsystem::Get(PLATFORM_SOCKETSUBSYSTEM)->CreateSocket(NAME_DGram, TEXT("UdpSocket"), true);

// 주목: Connect()가 없다! 연결을 안 맺으니 handshake도 없다. 그냥 "이 주소로 보내"
int32 BytesSent = 0;
FVector MyLocation = GetActorLocation();
UdpSocket->SendTo((uint8*)&MyLocation, sizeof(FVector), BytesSent, *ServerAddr);   // 도착 보장 없음. ACK도 재전송도 없음

// 받기 — 온 게 있으면 받고, 없으면 그냥 없는 것
if (UdpSocket->RecvFrom(Buffer, sizeof(Buffer), BytesRead, *Sender)) { /* 순서/유실은 내가 알아서 */ }
TCPUDP
Connect()로 연결을 먼저 맺음연결 없음
Send()SendTo()로 매번 목적지 지정 (연결이 없으니)
"도착하겠지" 믿어도 됨도착 여부는 내가 챙겨야 함

면접 포인트: "게임은 UDP를 쓰되, 중요한 데이터엔 애플리케이션 레벨에서 신뢰성을 직접 구현한다"고 답하면 깊이가 있다. "UDP라서 다 유실돼도 됨"은 얕은 답이다.
