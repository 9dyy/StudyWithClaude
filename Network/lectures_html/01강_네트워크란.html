Part 1 · 기초 · 멀티플레이는 왜 어려운가

네트워크란 무엇인가

싱글플레이는 "함수 호출"이고 멀티플레이는 "편지 보내기"다. 편지에 겹겹이 봉투가 씌워지는 캡슐화를 직접 눌러보며, 위치 12바이트를 보내는 데 왜 66바이트가 나가는지 확인한다.

SECTION 01 · 도입

1싱글플레이는 쉬웠는데, 멀티가 안 된다

싱글플레이에서 캐릭터 이동 코드는 단순하다. 입력이 들어오면 그 자리에서 위치를 바꾸면 끝 — 모든 게 같은 메모리, 같은 컴퓨터 안에 있으니까.

// 싱글플레이: 입력 → 바로 내 캐릭터 이동. 끝.
void AMyCharacter::Move(FVector Input)
{
    SetActorLocation(GetActorLocation() + Input * Speed * DeltaTime);
}

그런데 친구랑 같이 하는 게임이면, 내가 움직였을 때 다른 컴퓨터에 있는 친구 화면에서도 내가 움직여야 한다. 여기서 질문이 쏟아진다.

내 위치를 어떻게 보내지?

같은 메모리가 아니니 바이트로 만들어서 통신선에 실어야 한다.

보내는 도중에 사라지면?

패킷은 유실될 수 있다. 도착했는지 내가 어떻게 알지?

친구가 일본에 있으면?

거리만큼 늦게 도착한다. 지연(레이턴시)이 생긴다.

100명이 붙어 있으면?

누구한테 뭘 보내야 하지? 대역폭이 감당되나?

싱글플레이는 "함수 호출", 멀티플레이는 "편지 보내기"다. 봉투에 담고, 주소를 적고, 우체국(네트워크)에 맡기고, 도착하길 기도하는 일. 이걸 가능하게 하는 규칙과 장치 전체가 네트워크다.

SECTION 02 · 약속과 계층

2네트워크는 "약속의 더미"다

서울 PC와 부산 PC 사이엔 공유기, 통신사 장비, 해저 케이블, 서버 등 수십 개의 서로 다른 장비가 낀다. 제조사도 다 다르다. 이게 맞물려 도는 이유는 모두가 같은 약속, 즉 프로토콜(Protocol)을 지키기 때문이다. 그런데 하는 일이 너무 많아서 약속을 하나로 만들 수 없으니 역할별로 층을 나눴다.

택배로 보는 계층

📦 물건 담기 = 응용

내용물은 게임 데이터. 도로 사정은 몰라도 된다.

🏷️ 송장 = 전송·인터넷

어느 프로그램(포트)? 어느 컴퓨터(IP)?

🚚 트럭 = 네트워크 접근

옆 장비까지 실제로 옮긴다. 랜선이든 와이파이든.

OSI 7계층 → TCP/IP 4계층 (면접에선 둘 다 나온다)

OSI 7계층TCP/IP 4계층하는 일 · 게임에서
7 응용 · 6 표현 · 5 세션응용프로그램이 쓰는 데이터 형식. 위치 패킷, 로그인 요청, TLS·직렬화
4 전송전송어느 프로그램으로? 신뢰성? — TCP/UDP, 포트
3 네트워크인터넷어느 컴퓨터로? 경로 찾기 — IP 주소, 라우팅
2 데이터링크 · 1 물리네트워크 접근옆 장비로 전달 — MAC 주소, 이더넷, 랜선·와이파이

다 외울 필요 없다. 면접과 실무에서 99%는 4계층(전송)과 3계층(네트워크)이다. 4계층은 "어느 프로그램한테?"(포트), 3계층은 "어느 컴퓨터한테?"(IP)만 기억하자.

SECTION 03 · 핵심 · 직접 돌려보기

3캡슐화 시뮬레이터 — 층을 내려가며 봉투가 씌워진다

데이터를 고르고 [⬇ 한 층 내려가기]를 눌러보자. 각 층이 자기 정보를 헤더로 앞에 붙인다. [⬆ 한 겹 벗기기]는 받는 쪽의 역캡슐화다. 위치 패킷(12B)에서 TCP와 UDP를 바꿔가며 "게임 데이터가 전체의 몇 %인지" 보면 놀랄 것이다.

0

12

0%
헤더 비율

① 위치 패킷(12B)을 끝까지 내려보내자 → TCP면 66B 중 82%가 헤더, UDP면 54B 중 78%. 작은 패킷을 자주 보낼수록 헤더 비용이 커진다. ② 맵 데이터(4000B)로 바꿔보자 → 한 패킷에 못 들어가 여러 개로 쪼개진다(이더넷 한 프레임 = 최대 1500B, MTU). (이더넷 끝의 검사값 FCS 4B는 단순화를 위해 뺐다.)

SECTION 05 · 코드

5코드로 체감 — Replicated 한 줄의 정체

// 이 한 줄이 "캡슐화 → 전송 → 역캡슐화" 전체를 일으킨다
UPROPERTY(Replicated)
FVector ServerCharacterLocation;

void AMyCharacter::GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const
{
    Super::GetLifetimeReplicatedProps(OutLifetimeProps);
    DOREPLIFETIME(AMyCharacter, ServerCharacterLocation);   // "이 변수 다른 클라들한테도 보내줘"
}

우리가 보는 건 UPROPERTY(Replicated) 한 줄이지만 그 아래에서는 시뮬레이터가 보여준 일이 벌어진다.

단계하는 일계층
1ServerCharacterLocation을 바이트로 직렬화응용
2전송 프로토콜(언리얼은 기본 UDP 기반)에 실어 포트를 붙인다전송
3상대 클라의 IP로 보낼 주소를 붙인다인터넷
4랜선·와이파이로 실제 신호 전송접근
5상대 컴퓨터에서 한 겹씩 벗기고 FVector로 복원역방향

언리얼 네트워크 코드가 두꺼운 이유가 이거다. 개발자는 Replicated 한 줄이지만 엔진은 직렬화부터 패킷 전송, 유실 처리, 순서 보정까지 다 해준다. 그 안에서 뭐가 도는지 아는 게 이 시리즈의 목표다.
