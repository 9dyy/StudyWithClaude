SECTION 01 · 종합

1지금까지 배운 게 다 여기서 만난다

TCP/UDP 선택? → 엔진이 UDP 기반 + 신뢰성 선택(6강)으로 해결. 패킷 직렬화·경계? → 엔진이 자동 처리(10강). 클라 믿지 마라? → 서버 권한 구조로 강제(13강).

언리얼은 이 저수준을 다 가려주고, 우리는 세 가지 도구만 쓴다: 서버 권한, Replication, RPC.

SECTION 02 · 철학

2서버 권한 — "서버가 진실, 클라는 화면"

적 HP, 내 위치, 아이템 개수 — 진짜 값은 전부 서버에 있다. 클라는 그 복사본을 보여준다.

if (HasAuthority())   // 이 액터에 대한 권한이 있나 = 서버인가
{
    // 서버에서만 도는 코드 (실제 게임 로직, 판정)
}
else
{
    // 클라에서 도는 코드 (표현, 예측)
}

중요한 판정(데미지, 재화, 사망)은 전부 HasAuthority() 안, 즉 서버에서 해야 한다.

SECTION 03 · 상태 동기화

3Replication — 서버 상태를 클라로 자동 복제

UPROPERTY(ReplicatedUsing = OnRep_Health)
float Health = 100.f;

void AMyCharacter::OnRep_Health()
{
    UpdateHealthBar(Health);   // 클라에서 값이 바뀌면 자동 호출 → 화면 갱신
}

단방향: 서버 → 클라. 클라가 복제 변수를 바꿔도 서버엔 안 간다(보안). HP·위치처럼 지속 상태 동기화에 적합하고, 6강의 신뢰성 UDP로 도착이 보장된다.

SECTION 04 · 이벤트성 동작

4RPC — 한쪽에서 다른 쪽 함수를 실행

RPC 종류호출하는 곳실행되는 곳
Server클라서버
Client서버그 클라 한 명
Multicast서버모든 클라 (+서버)
UFUNCTION(Server, Reliable)
void Server_RequestAttack(int32 TargetId);      // 클라 → 서버: "이거 해줘"

UFUNCTION(Client, Reliable)
void Client_OnLevelUp(int32 NewLevel);        // 서버 → 특정 클라: "너한테만"

UFUNCTION(NetMulticast, Unreliable)
void Multicast_PlayExplosion(FVector Location); // 서버 → 모두: "다같이 봐"

신뢰성도 6강 그대로 적용된다. Reliable: 공격 요청·레벨업처럼 놓치면 안 되는 것. Unreliable: 이펙트·사운드처럼 유실 OK인 것.
