IP 주소와 라우팅

SECTION 01 · 도입

1"친구랑 직접 연결"이 안 되는 이유

P2P 게임을 만든다. 친구랑 직접 연결하면 서버 비용도 안 들고 좋다. 친구한테 IP를 물어본다.

나:   네 IP 뭐야?
친구: 192.168.0.5
나:   어? 나도 192.168.0.5인데?

둘 다 같은 IP인데 분명 다른 집, 다른 컴퓨터다. 이게 어떻게 가능하지?

// 친구가 알려준 IP로 연결 시도
FString FriendIP = TEXT("192.168.0.5");
Connect(FriendIP, 7777);   // ❌ 연결 안 됨. 왜?

이 강의가 끝나면 이 코드가 왜 실패하는지, 그리고 매치메이킹 서버가 왜 필요한지 알게 된다. 아래 시뮬레이터에서 직접 확인한다.

SECTION 02 · IP 주소

2IP 주소 — 컴퓨터의 주소

IP 주소는 네트워크 상에서 컴퓨터를 식별하는 주소다. 1강의 3계층(인터넷 계층)에서 쓰고, "어느 컴퓨터로 보낼까"를 정한다.

IPv4 · 32비트

192.168.0.5 — 8비트씩 4칸(각 0~255). 약 43억 개(2³²). 전 세계 PC·폰·서버·IoT를 생각하면 이미 부족하다.

IPv6 · 128비트

2001:0db8:85a3::8a2e:0370:7334 — 16비트씩 8칸, 16진수. 사실상 무한(2¹²⁸). IPv4 고갈 때문에 나왔다.

면접에선 "IPv4가 고갈돼서 128비트로 늘린 게 IPv6" 정도면 충분하다. IPv4 고갈을 완화한 게 뒤에 나올 사설 IP + NAT다.

SECTION 03 · 서브넷 · 직접 계산

3IP는 "네트워크 부분 + 호스트 부분"

IP 주소는 한 덩어리가 아니다. 앞쪽은 네트워크(동네), 뒤쪽은 호스트(집)다. /24는 "앞 24비트가 네트워크"라는 뜻이다. 두 IP를 넣고 접두사를 바꿔보자. 파란 비트가 네트워크 부분이다.

① 기본값: .5와 .99는 같은 동네 → 라우터 없이 직접 전달. ② 192.168.1.5로 바꾸면 다른 동네 → 게이트웨이(공유기)를 거쳐야 한다. ③ 같은 192.168.0.5끼리 비교하면 "같은 IP"인데, 그게 서로 다른 집이면 별개 컴퓨터라는 게 사설 IP의 정체다(5절).

SECTION 04 · 라우팅

4라우팅 — 패킷이 길을 찾아가는 법

서울 PC에서 미국 서버까지 가려면 중간에 수십 개의 라우터를 거친다. 라우터는 "이 목적지로 가려면 다음에 어디로 보내야 하나"를 아는 교차로의 교통경찰이다.

내 PC ──→ 공유기 ──→ 통신사 라우터 ──→ ... ──→ 해저케이블 ──→ ... ──→ 미국 서버
         (게이트웨이)                  (수십 홉)

각 라우터는 "다음 한 칸"만 안다

전체 경로를 아는 게 아니다. "미국 방향이면 저쪽 라우터로" 하고 바통을 넘긴다. 한 칸이 홉(hop).

내비게이션이 아니라 이정표

갈림길마다 표지판(라우팅 테이블)을 보고 나아간다. 그래서 라우터 하나가 죽어도 우회가 가능하다.

> tracert google.com     // 윈도우. 게임 핑 디버깅에 가끔 쓴다
 1    1 ms   공유기 (192.168.0.1)
 2   10 ms   통신사 라우터
 3   12 ms   ...        (각 줄이 라우터 하나 = 1홉)
SECTION 05 · 핵심 · 직접 돌려보기

5사설 IP · NAT — 그리고 P2P 연결 시도

도입의 미스터리가 여기서 풀린다. 사설 IP(10.x, 172.16~31.x, 192.168.x)는 집·회사 내부에서만 쓰는 주소라 서로 다른 집에 같은 게 있어도 된다(아파트마다 101호가 있는 것과 같다). 공인 IP는 통신사가 공유기에 주는 인터넷 전체에서 유일한 주소고, 공유기의 NAT가 사설↔공인을 번역하며 기억해둔다.

위에서부터 하나씩 눌러보자. ① 친구의 사설 IP는 내 LAN 안에서 찾다가 나 자신에게 간다. ② 공인 IP로 쏘면 친구 공유기 NAT 테이블에 "누구한테 줘야 하는지" 항목이 없어 버려진다. ③ 해법은 서버 중계(대부분의 게임)나 홀 펀칭(P2P가 꼭 필요할 때).

SECTION 06 · 코드

6언리얼에서 접속 주소를 다룰 때

// (1) 서버 접속 — 보통 사설 IP가 아니라 공인 IP나 도메인을 쓴다
UGameplayStatics::OpenLevel(this, TEXT("203.0.113.10"), true, TEXT("?port=7777"));
//                                  └ 공인 IP. 사설 IP였다면 외부에서 접속 불가

// (2) 내 로컬 IP 확인 — 보통 192.168.x.x (사설)
bool bCanBind = false;
TSharedRef<FInternetAddr> LocalAddr =
    ISocketSubsystem::Get(PLATFORM_SOCKETSUBSYSTEM)->GetLocalHostAddr(*GLog, bCanBind);
UE_LOG(LogTemp, Log, TEXT("My IP: %s"), *LocalAddr->ToString(false));
// 출력 예: 192.168.0.5  ← 우리 집 안에서만 통하는 주소

// (3) 같은 PC에서 서버-클라 테스트할 땐 루프백 주소
Connect(TEXT("127.0.0.1"), 7777);   // 127.0.0.1 = localhost = "나 자신". 네트워크 안 타고 내 PC 안에서 돈다

127.0.0.1(루프백)은 외워두자. "내 컴퓨터 자신"을 가리키는 특수 주소다. 서버와 클라를 같은 PC에서 띄워 테스트할 때 매일 쓴다. 서브넷 계산기에 127.0.0.1을 넣어보면 태그가 다르게 나온다.
