TCP vs UDP, 게임은 뭘 쓰나

"TCP요" 또는 "UDP요"로 답하면 얕은 답이다. 좋은 멀티플레이 게임은 데이터 성격에 따라 둘 다 쓴다. 직접 데이터를 분류해보고 선택 기준을 몸에 익힌다.

SECTION 01 · 문제

1"그래서 우리 게임은 뭘 써요?"

신입이 멀티플레이 기능을 맡으면 가장 먼저 부딪히는 질문. 채팅은? 위치 동기화는? 로그인은? 아이템 거래는?

답을 "TCP요" 또는 "UDP요" 하나로 못 한다. 데이터마다 다르다. 좋은 멀티플레이 게임은 거의 항상 둘 다 쓴다.

면접에서 "TCP랑 UDP 중 뭐가 좋아요?"라고 물으면, "데이터 성격에 따라 다릅니다"로 시작하는 게 정답이다. 하나만 찍으면 얕은 답이다.

SECTION 04 · 실전

4둘을 섞어 쓴다 — 하이브리드

실제 게임은 한 클라이언트가 TCP 연결과 UDP 연결을 동시에 유지하는 경우가 많다. MMORPG 예시:

게임 클라이언트
TCP 채널
접속·로그인
길드 채팅
아이템 거래
UDP 채널
캐릭터 이동 동기화
스킬 이펙트 위치

"게임은 UDP만 쓴다"도 "TCP만 쓴다"도 틀렸다. 정상은 데이터별로 섞어 쓰는 것이다.

SECTION 05 · 면접 깊이 포인트

5신뢰성 UDP — 골라서 신뢰성

"플레이어가 죽었다" 같은 이벤트는 UDP 채널로 흐르는데 반드시 도착해야 한다. TCP를 통째로 또 연결하긴 부담스럽다. 해법: UDP 위에 필요한 패킷만 시퀀스 번호 + ACK + 재전송을 얹는다.

TCP — 전부 신뢰성 (Head-of-Line 블로킹)
신뢰성 UDP — 위치는 그냥 흐르고, 이벤트만 재전송

버튼을 눌러 패킷 3번이 유실됐을 때 TCP와 신뢰성 UDP가 어떻게 다르게 반응하는지 비교해보자.

언리얼 RPC도 이 철학이다. 데이터마다 신뢰성을 직접 고른다.

UFUNCTION(Server, Reliable)      // 반드시 도착 (거래, 사망 처리 등)
void Server_RequestTrade(int32 ItemId);

UFUNCTION(Server, Unreliable)    // 유실 OK (이동 입력 등 자주 갱신되는 것)
void Server_SendMoveInput(FVector Input);
