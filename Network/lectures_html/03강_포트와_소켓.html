포트와 소켓

IP는 "어느 컴퓨터"까지만 정한다. 그 안의 어느 프로그램에 줄지는 포트가, 그리고 연결 하나를 유일하게 가리키는 건 네 개의 값이다. 패킷을 직접 만들어 던져보며 서버가 어떻게 수천 명을 구분하는지 확인한다.

🏢 IP는 동, 포트는 호수
🧩 선수지식 2강
⏱️ 약 15분
SECTION 01 · 도입

1IP만으론 부족하다

내 PC에서 게임 클라이언트, 크롬(유튜브), 디스코드가 동시에 돈다. 셋 다 같은 공인 IP 하나를 쓴다. 서버가 보낸 패킷이 우리 집에 도착했을 때, 이걸 누구한테 줘야 할까?

게임 서버 → (우리 집 공인 IP 1.2.3.4로 패킷 도착) → ???
                                                  게임? 크롬? 디스코드?

IP는 "어느 컴퓨터"까지만 정한다. 그 컴퓨터 안의 어느 프로그램한테 줄지는 IP만으로는 모른다. 이걸 정하는 게 포트(Port)다.

SECTION 02 · 포트

2포트 — 프로그램의 번호표

포트는 컴퓨터 안에서 프로그램을 구분하는 번호다. 16비트라서 0 ~ 65535. 4계층(전송 계층)에서 쓴다.

🏢 IP = 아파트 동

어느 컴퓨터(건물)인지. 동만 알면 어느 집인지 모른다.

🚪 포트 = 호수

그 컴퓨터의 어느 프로그램(집)인지. 호수만 알면 어느 아파트인지 모른다.

패킷이 도착하면 OS가 포트 번호를 보고 분배:

1.2.3.4 : 7777   → 게임 클라이언트
1.2.3.4 : 50123  → 크롬 (유튜브 탭)
1.2.3.4 : 50124  → 디스코드
   ↑        ↑
  IP       포트
(어느 PC)  (어느 프로그램)

각 프로그램은 자기 포트를 "내 거"라고 OS에 등록(bind)해두고, OS는 그 포트로 온 패킷만 그 프로그램에 넘긴다.

Well-known 포트 (0~1023)용도
80HTTP (웹)
443HTTPS (보안 웹)
53DNS
22SSH

게임은 이 예약 구간을 피해서 7777, 27015 같은 높은 번호를 쓴다. 언리얼 기본 게임 포트가 7777이다.

SECTION 03 · 소켓

3소켓 — 통신의 손잡이, 그리고 4-tuple

소켓은 "IP + 포트" 한 쌍으로 만들어지는 통신의 끝점(endpoint)이다. 프로그램 입장에선 파일 핸들처럼 다루는 창구 — 여기에 send/recv한다.

소켓 = IP 주소 + 포트 번호

내 게임 클라:  192.168.0.5   : 50200   ← 내 쪽 소켓
게임 서버:     203.0.113.10  : 7777    ← 서버 쪽 소켓

이 두 소켓을 잇는 게 "연결(connection)"

OS 강의와 연결: 소켓은 OS가 핸들로 관리하는 자원이다. 파일 디스크립터처럼 다 쓰면 닫아줘야 한다(close). 안 닫으면 누수된다.

클라 100명이 전부 7777로 접속하면 서버는 어떻게 구분할까?

연결 하나는 4개 값(4-tuple)으로 유일하게 식별된다.

( 출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트 )

플레이어A: (1.1.1.1, 50200, 203.0.113.10, 7777)
플레이어B: (2.2.2.2, 51000, 203.0.113.10, 7777)
            └─ 클라마다 IP/포트가 달라서 ─┘
            서버 포트는 같아도 연결은 구분된다

서버는 포트 하나(7777)로 듣고 있지만, 접속해오는 클라마다 IP·포트 조합이 다르니 연결은 전부 구분된다. 이게 "서버 하나가 수천 명을 받는 원리"의 답이다.

SECTION 04 · 핵심 · 직접 돌려보기

4패킷 배달 시뮬레이터 — 서버는 이걸 어떻게 가르나

아래 서버는 203.0.113.10:7777에서 듣고 있다. 출발지 IP·포트, 목적지 포트, 종류(접속 요청 SYN / 데이터)를 골라 패킷을 던져보자. 서버 OS가 4-tuple 표를 보고 어떻게 처리하는지가 결과로 나온다.

🖥️ 서버 203.0.113.10듣는 포트 7777연결 0개서로 다른 4-tuple 0개
패킷을 보내면 서버 OS의 판단이 여기 표시된다.

① 표에서 목적지 IP·포트는 모든 행이 같다(회색). 구분해주는 건 출발지(청록)뿐이다. ② 같은 집(1.1.1.1)에서 두 프로그램이 접속해도 출발지 포트가 다르면 별개 연결이다. ③ 이미 있는 4-tuple로 SYN을 또 보내도 새 연결은 안 생긴다. ④ 100명을 접속시켜도 서버 포트는 7777 하나다.

SECTION 05 · 코드

5언리얼 FSocket으로 보면

엔진이 가려주지만, 그 아래에서 소켓은 이렇게 생겼다. 핵심은 "어느 컴퓨터(IP) + 어느 프로그램(포트)"를 둘 다 지정한다는 것.

// 소켓 하나 생성 — OS에 "통신 창구 하나 줘" 요청
FSocket* Socket = ISocketSubsystem::Get(PLATFORM_SOCKETSUBSYSTEM)
    ->CreateSocket(NAME_Stream, TEXT("MySocket"), false);
//                 ↑ NAME_Stream = TCP용 (4강에서 다룸)

// 목적지 주소(소켓 끝점) 구성: IP + 포트
TSharedRef<FInternetAddr> ServerAddr =
    ISocketSubsystem::Get(PLATFORM_SOCKETSUBSYSTEM)->CreateInternetAddr();
bool bValid;
ServerAddr->SetIp(TEXT("203.0.113.10"), bValid);   // 어느 컴퓨터 (IP)
ServerAddr->SetPort(7777);                          // 어느 프로그램 (포트)

// 연결 시도 — 내 소켓과 서버 소켓을 잇는다
bool bConnected = Socket->Connect(*ServerAddr);

// 다 쓰면 반드시 닫기 (OS 자원 해제)
Socket->Close();
ISocketSubsystem::Get(PLATFORM_SOCKETSUBSYSTEM)->DestroySocket(Socket);

실무에서 raw 소켓 코드를 직접 쓰는 일은 드물다. 보통 Replication(14강)이나 HTTP 모듈(11강)을 쓴다. 다만 "그 아래에서 소켓이 이렇게 돈다"는 건 알아야 면접에서 막히지 않는다.
