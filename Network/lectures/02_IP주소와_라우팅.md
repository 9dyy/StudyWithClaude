# 2강 — IP 주소와 라우팅

> **목표:** 내 패킷이 전 세계 컴퓨터 중에 어떻게 정확히 목적지 PC를 찾아가는지, 그리고 공인/사설 IP와 NAT가 멀티플레이에서 왜 문제가 되는지 이해한다.
> **선수 지식:** 1강(계층 모델, 캡슐화).

---

## 1. "친구랑 직접 연결" 이 안 되는 이유

P2P 게임을 만든다고 하자. 친구랑 직접 연결하면 서버 비용도 안 들고 좋다. 친구한테 IP를 물어본다.

```
나:   네 IP 뭐야?
친구: 192.168.0.5
나:   어? 나도 192.168.0.5인데?
```

둘 다 같은 IP다. 그런데 둘은 분명 다른 집, 다른 컴퓨터다. **이게 어떻게 가능하지?**

```cpp
// 친구가 알려준 IP로 연결 시도
FString FriendIP = TEXT("192.168.0.5");
Connect(FriendIP, 7777);   // ❌ 연결 안 됨. 왜?
```

이 강의가 끝나면 왜 이 코드가 실패하는지, 그리고 매치메이킹 서버가 왜 필요한지 알게 된다. 먼저 IP 주소부터 보자.

---

## 2. IP 주소 — 컴퓨터의 주소

IP 주소는 **네트워크 상에서 컴퓨터를 식별하는 주소**다. 1강의 계층으로 치면 3계층(네트워크 계층)에서 쓴다. "어느 컴퓨터로 보낼까"를 정하는 게 IP다.

### IPv4

우리가 제일 많이 보는 형태. 32비트를 8비트씩 4칸으로 끊어서 점으로 쓴다.

```
192 . 168 . 0 . 5
 ↑     ↑    ↑   ↑
각 칸은 0~255 (8비트 = 2^8 = 256가지)
```

전체 32비트니까 약 **43억 개**(2^32)의 주소를 만들 수 있다. 많아 보이지만, 전 세계 PC·폰·서버·IoT 기기를 생각하면 **이미 부족하다.** 이걸 해결하려고 나온 게 사설 IP(뒤에 나옴)와 IPv6다.

### IPv6

IPv4 고갈 때문에 나온 차세대 주소. 128비트라서 사실상 무한하다(2^128).

```
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

16비트씩 8칸, 16진수로 쓴다. 면접에선 "IPv4가 고갈돼서 128비트로 늘린 게 IPv6" 정도만 알면 충분하다.

---

## 3. 서브넷 — IP는 "네트워크 부분 + 호스트 부분"

IP 주소는 그냥 한 덩어리가 아니다. **앞쪽은 네트워크(동네), 뒤쪽은 호스트(집)** 를 나타낸다.

```
192.168.0.5 / 24
└─────┬────┘ └┬┘
  네트워크부분  └ 서브넷 마스크: 앞 24비트가 네트워크라는 뜻

192 . 168 . 0 . 5
└──── 네트워크 ────┘ └호스트┘
   (앞 24비트)      (뒤 8비트)
```

`/24`는 "앞 24비트가 네트워크 주소"라는 뜻이다. 그래서:

- `192.168.0.x` 는 같은 동네 (같은 네트워크)
- `192.168.0.5` 와 `192.168.0.99` 는 같은 동네의 다른 집
- `192.168.1.5` 는 다른 동네

이게 왜 중요하냐면, **같은 동네면 라우터 없이 바로 전달**하고, **다른 동네면 라우터(게이트웨이)를 거쳐야** 하기 때문이다. 우편으로 치면 같은 아파트 단지 안은 경비실이 직접 전해주고, 다른 도시면 우체국을 거치는 것과 같다.

---

## 4. 라우팅 — 패킷이 길을 찾아가는 법

서울 내 PC에서 미국 서버까지 패킷이 가려면, 중간에 수십 개의 **라우터(Router)** 를 거친다. 라우터는 "이 목적지로 가려면 다음에 어디로 보내야 하나"를 아는 교차로의 교통경찰이다.

```
내 PC ──→ 공유기 ──→ 통신사 라우터 ──→ ... ──→ 해저케이블 ──→ ... ──→ 미국 서버
         (게이트웨이)                    (수십 홉)
```

각 라우터는 전체 경로를 모른다. **"다음 한 칸"만 안다.** "미국 방향이면 일단 저쪽 라우터로 넘겨" 하는 식으로 바통을 넘긴다. 이 한 칸 한 칸을 **홉(hop)** 이라고 부른다.

> **핵심 비유:** 라우팅은 내비게이션이 아니라 **이정표 따라가기**다. 출발할 때 전체 경로를 다 아는 게 아니라, 갈림길마다 "○○ 방면 →" 표지판을 보고 한 칸씩 나아간다. 표지판(라우팅 테이블)은 각 라우터가 갖고 있다.

`tracert`(윈도우) 명령으로 실제 홉을 볼 수 있다. 게임 핑 문제 디버깅할 때 가끔 쓴다.

```
> tracert google.com
 1    1 ms   공유기 (192.168.0.1)
 2   10 ms   통신사 라우터
 3   12 ms   ...
 ...
 (각 줄이 라우터 하나 = 1홉)
```

## 5. 공인 IP vs 사설 IP, 그리고 NAT — 도입의 미스터리 풀기

1번에서 나랑 친구 IP가 둘 다 `192.168.0.5`였던 이유가 여기 있다.

### 사설 IP (Private IP)

집/회사 **내부에서만** 쓰는 IP다. 인터넷 전체에선 안 통한다. 정해진 대역이 있다.

| 대역 | 범위 |
|------|------|
| 10.x.x.x | 10.0.0.0 ~ 10.255.255.255 |
| 172.16~31.x.x | 172.16.0.0 ~ 172.31.255.255 |
| 192.168.x.x | 192.168.0.0 ~ 192.168.255.255 |

`192.168.0.5`는 사설 IP다. **우리 집 안에서만** 의미가 있다. 친구네 집에도 똑같이 `192.168.0.5`가 있을 수 있다 — 서로 다른 동네라 안 겹치니까. 아파트마다 101호가 다 있는 것과 같다.

### 공인 IP (Public IP)

인터넷 전체에서 **유일한** 주소. 통신사가 공유기에 하나 준다. 우리 집의 "대표 주소"다.

### NAT — 사설을 공인으로 번역

집 안엔 PC, 노트북, 폰이 다 사설 IP를 갖고 있다. 그런데 인터넷에 나갈 땐 공인 IP가 하나뿐이다. 이걸 중계해주는 게 공유기의 **NAT(Network Address Translation)** 다.

```
[집 내부]                  공유기(NAT)              [인터넷]
PC   192.168.0.5  ┐
폰   192.168.0.6  ┼──→  공인 IP 1.2.3.4  ──→   게임 서버
노트북 192.168.0.7 ┘     (포트로 누가 누군지 구분)
```

공유기가 "내부 192.168.0.5가 보낸 거니까, 응답 오면 다시 걔한테 줘야지" 하고 **주소를 바꿔치기하며 기억**해둔다. 나갈 땐 사설→공인, 들어올 땐 공인→사설.

### 그래서 도입 코드가 실패한 이유

친구가 알려준 `192.168.0.5`는 **친구네 집 안에서만 통하는 사설 IP**다. 내가 그 주소로 연결을 시도하면, 내 공유기는 "어? 192.168.0.5는 우리 집 내부 주소인데?" 하고 엉뚱하게 우리 집 안에서 찾는다. 친구한테 도달할 방법이 없다.

이게 **P2P 게임이 어려운 핵심 이유**다. 둘 다 NAT 뒤에 숨어 있어서 서로의 진짜 위치를 직접 못 찾는다. 그래서:

1. 보통은 **중앙 서버**를 둔다. 둘 다 공인 IP를 가진 서버에 접속하고, 서버가 중계한다.
2. P2P가 꼭 필요하면 **NAT 홀 펀칭** 같은 기법을 쓴다(STUN 서버로 서로의 공인 IP:포트를 알아내서 직접 뚫기). 까다로워서 면접에선 "NAT 때문에 P2P가 어렵고, 보통 서버를 두거나 홀 펀칭을 쓴다" 정도면 충분하다.

## 6. 코드로 체감해보기

언리얼에서 접속 주소를 다룰 때 이 개념들이 그대로 나온다.

```cpp
// (1) 서버 접속 — 보통 사설 IP가 아니라 공인 IP나 도메인을 쓴다
UGameplayStatics::OpenLevel(this, TEXT("203.0.113.10"), true, TEXT("?port=7777"));
//                                  └ 공인 IP. 사설 IP였다면 외부에서 접속 불가

// (2) 내 로컬 IP 확인 — 보통 192.168.x.x (사설)
bool bCanBind = false;
TSharedRef<FInternetAddr> LocalAddr =
    ISocketSubsystem::Get(PLATFORM_SOCKETSUBSYSTEM)->GetLocalHostAddr(*GLog, bCanBind);
UE_LOG(LogTemp, Log, TEXT("My IP: %s"), *LocalAddr->ToString(false));
// 출력 예: 192.168.0.5  ← 이건 우리 집 안에서만 통하는 주소

// (3) 같은 PC에서 서버-클라 테스트할 땐 루프백 주소
Connect(TEXT("127.0.0.1"), 7777);   // 127.0.0.1 = localhost = "나 자신". 네트워크 안 타고 내 PC 안에서 돈다
```

`127.0.0.1`(루프백)은 외워두면 좋다. **"내 컴퓨터 자신"** 을 가리키는 특수 주소다. 서버랑 클라를 같은 PC에서 띄워 테스트할 때 매일 쓴다.

## 7. 흔한 오해

### 오해 1: "내 IP는 고정이다"

대부분의 가정용 인터넷은 **유동 IP**다. 통신사가 공인 IP를 그때그때 빌려준다. 재접속하면 바뀔 수 있다. 그래서 "내 서버 주소"를 IP로 박아두면 언젠가 안 통한다. 이걸 해결하려고 도메인(DNS)을 쓴다 (12강).

### 오해 2: "사설 IP는 보안 기능이다"

사설 IP와 NAT가 결과적으로 외부에서 내부로 직접 못 들어오게 막아주는 효과는 있다. 하지만 그건 **부수 효과**지 보안 목적으로 설계된 게 아니다. 진짜 보안은 방화벽과 암호화(TLS, 13강)가 담당한다.

### 오해 3: "IP만 알면 데이터를 보낼 수 있다"

IP는 "어느 컴퓨터"까지만 정한다. 그 컴퓨터의 **어느 프로그램**한테 줄지는 IP만으론 모른다. 게임 클라이언트인지 크롬인지 구분하는 건 **포트**의 일이다 (3강). IP는 아파트 동, 포트는 호수라고 보면 된다.

### 오해 4: "라우터는 전체 경로를 알고 있다"

각 라우터는 **다음 한 홉**만 안다. 전체 경로를 미리 계산해놓는 게 아니라, 패킷이 올 때마다 "이 목적지면 다음은 저기" 하고 한 칸씩 넘긴다. 그래서 중간에 한 라우터가 죽어도 다른 경로로 우회가 가능하다.

## 8. 면접에서 나오면

**Q1. IP 주소가 뭔가요?**
→ "네트워크 상에서 컴퓨터를 식별하는 주소입니다. OSI의 네트워크 계층에서 사용하고, '어느 컴퓨터로 보낼지'를 결정합니다. IPv4는 32비트로 약 43억 개를 표현하고, 고갈 문제 때문에 128비트인 IPv6가 나왔습니다."

**Q2. 공인 IP와 사설 IP의 차이는?**
→ "공인 IP는 인터넷 전체에서 유일한 주소고, 사설 IP는 집이나 회사 내부에서만 쓰는 주소입니다. 192.168.x.x 같은 게 사설 IP인데, 내부망에서만 의미가 있어서 서로 다른 집에 같은 사설 IP가 있을 수 있습니다. 외부로 나갈 땐 공유기가 NAT로 사설 IP를 공인 IP로 변환합니다."

**Q3. NAT가 뭔가요?**
→ "사설 IP를 공인 IP로 변환해주는 기술입니다. 집 안에 여러 기기가 있어도 공인 IP는 하나뿐이라, 공유기가 내부 기기들의 주소를 공인 IP로 바꿔서 내보내고, 응답이 오면 어느 기기 것인지 기억했다가 되돌려줍니다. 주소 부족 문제를 완화하는 효과도 있습니다."

**Q4. 라우팅이 뭔가요?**
→ "패킷이 목적지까지 가는 경로를 결정하는 과정입니다. 각 라우터는 전체 경로가 아니라 다음에 어디로 보낼지(다음 홉)만 알고, 라우팅 테이블을 보고 한 단계씩 패킷을 전달합니다. 이렇게 홉을 거치다 보면 목적지에 도착합니다."

**Q5. P2P 게임에서 NAT가 왜 문제가 되나요?**
→ "양쪽 플레이어가 모두 NAT 뒤의 사설 IP를 쓰기 때문에, 서로의 진짜 주소로 직접 연결할 수가 없습니다. 그래서 보통은 공인 IP를 가진 중앙 서버를 두고 중계하거나, STUN 서버로 서로의 공인 주소를 알아내 직접 뚫는 NAT 홀 펀칭 기법을 씁니다."

**Q6. 127.0.0.1이 뭔가요?**
→ "루프백 주소로, 자기 자신을 가리키는 특수 IP입니다. 네트워크를 실제로 타지 않고 자기 컴퓨터 내부에서 처리되기 때문에, 서버와 클라이언트를 같은 PC에서 띄워 테스트할 때 자주 씁니다."

면접관이 그 다음에 던지기 좋은 질문: *"그럼 한 컴퓨터 안에서 게임 클라랑 브라우저는 어떻게 구분해서 데이터를 받나요?"* → 3강(포트와 소켓)에서 다룬다.

## 9. 셀프 체크

- [ ] IPv4와 IPv6의 차이(비트 수, 왜 IPv6가 나왔는지)를 말할 수 있다.
- [ ] 공인 IP와 사설 IP의 차이를 설명하고, 사설 IP 대역 하나는 댈 수 있다.
- [ ] NAT가 무슨 일을 하는지 그림으로 설명할 수 있다.
- [ ] 라우터가 "다음 홉만 안다"는 의미를 이해했다.
- [ ] 친구의 사설 IP로 직접 접속이 안 되는 이유를 설명할 수 있다.
- [ ] 127.0.0.1이 뭔지 안다.
