# 1강 — 네트워크란 무엇인가?

> **목표:** "멀티플레이는 왜 어려운가"를 네트워크 관점에서 감 잡고, OSI 계층과 캡슐화가 왜 나왔는지 이해한다.
> **선수 지식:** 없음. 싱글플레이 게임을 한 번 만들어봤으면 충분.

---

## 1. 싱글플레이는 쉬웠는데, 멀티가 안 된다

싱글플레이 게임에서 캐릭터를 움직이는 코드는 단순하다.

```cpp
// 싱글플레이: 입력 → 바로 내 캐릭터 이동. 끝.
void AMyCharacter::Move(FVector Input)
{
    SetActorLocation(GetActorLocation() + Input * Speed * DeltaTime);
}
```

입력이 들어오면 그 자리에서 위치를 바꾸면 된다. 모든 게 **같은 메모리, 같은 컴퓨터** 안에 있으니까.

그런데 친구랑 같이 하는 게임을 만든다고 해보자. 내 캐릭터가 움직이면, **다른 컴퓨터에 있는** 친구 화면에서도 내가 움직여야 한다.

여기서 문제가 시작된다.

- 내 위치를 어떻게 친구 컴퓨터로 보내지?
- 보내는 도중에 데이터가 사라지면?
- 친구가 일본에 있고 나는 한국에 있으면, 그 거리만큼 늦게 도착하는데?
- 같은 게임에 100명이 붙어 있으면 누구한테 뭘 보내야 하지?

**싱글플레이는 "함수 호출"이고, 멀티플레이는 "편지 보내기"다.** 내 데이터를 봉투에 담아서, 주소를 적고, 우체국(네트워크)에 맡기고, 도착하길 기도하는 일. 이걸 가능하게 해주는 규칙과 장치 전체가 **네트워크**다.

---

## 2. 네트워크는 "약속의 더미"다

서울에 있는 내 PC와 부산에 있는 친구 PC가 데이터를 주고받으려면, 그 사이엔 공유기, 통신사 장비, 해저 케이블, 서버 등 **수십 개의 서로 다른 장비**가 낀다. 제조사도 다 다르다.

이게 어떻게 다 맞물려 돌아갈까? **모두가 같은 약속(프로토콜, Protocol)을 지키기 때문**이다.

프로토콜은 "데이터를 이런 형식으로, 이런 순서로 주고받자"는 통신 규약이다. 사람으로 치면 "편지 봉투엔 받는 사람 주소를 오른쪽 아래에 쓴다" 같은 약속.

그런데 네트워크가 하는 일이 너무 많아서, 약속을 **하나로** 만들면 너무 복잡하다. 그래서 **역할별로 층을 나눴다.** 이게 계층 모델이다.

> **핵심 비유:** 택배를 생각해보자.
> - 나는 **물건**만 상자에 담는다 (내용물 = 게임 데이터)
> - 택배 회사는 **송장**을 붙인다 (주소 = IP)
> - 트럭 기사는 **도로**로 옮긴다 (물리적 전송)
>
> 각자 자기 일만 한다. 물건 담는 사람이 도로 사정까지 알 필요 없다. 네트워크도 똑같이 층을 나눈다.

---

## 3. OSI 7계층과 TCP/IP 4계층

교과서는 **OSI 7계층**으로 가르친다. 실무는 **TCP/IP 4계층**으로 돈다. 면접에선 둘 다 물어본다.

| OSI 7계층 | 하는 일 | 게임에서 |
|-----------|---------|----------|
| 7. 응용 (Application) | 프로그램이 쓰는 데이터 형식 | 로그인 요청, 캐릭터 위치 패킷 |
| 6. 표현 (Presentation) | 암호화, 인코딩 | TLS 암호화, 직렬화 |
| 5. 세션 (Session) | 연결 유지/관리 | 접속 세션 |
| 4. 전송 (Transport) | 어느 프로그램으로? 신뢰성 | **TCP / UDP, 포트** |
| 3. 네트워크 (Network) | 어느 컴퓨터로? 경로 찾기 | **IP 주소, 라우팅** |
| 2. 데이터링크 (Data Link) | 옆 장비로 전달 | MAC 주소, 이더넷 |
| 1. 물리 (Physical) | 실제 전기/빛 신호 | 랜선, 와이파이 |

실무에서 자주 쓰는 **TCP/IP 4계층**은 이걸 묶은 거다.

```
OSI 7계층                  TCP/IP 4계층
┌──────────────┐
│ 7. 응용      │
│ 6. 표현      │  ──→     ┌──────────────┐
│ 5. 세션      │          │ 응용 계층    │   HTTP, 게임 패킷
├──────────────┤          ├──────────────┤
│ 4. 전송      │  ──→     │ 전송 계층    │   TCP, UDP
├──────────────┤          ├──────────────┤
│ 3. 네트워크  │  ──→     │ 인터넷 계층  │   IP
├──────────────┤          ├──────────────┤
│ 2. 데이터링크│          │ 네트워크     │   이더넷, 와이파이
│ 1. 물리      │  ──→     │ 접근 계층    │
└──────────────┘          └──────────────┘
```

**다 외울 필요 없다.** 면접과 실무에서 99% 쓰는 건 **4계층(전송)과 3계층(네트워크)** 이다. 이 시리즈도 거기에 시간을 제일 많이 쓴다. 4계층은 "어느 프로그램한테?"(포트), 3계층은 "어느 컴퓨터한테?"(IP)를 담당한다고만 기억하면 된다.

---

## 4. 캡슐화 — 층을 내려가며 봉투가 겹겹이 씌워진다

계층 모델의 핵심 동작이 **캡슐화(Encapsulation)** 다. 면접 단골이다.

내 게임이 "캐릭터 위치 (100, 50, 0)"을 친구한테 보낸다고 하자. 이 데이터가 위층에서 아래층으로 내려가면서, **각 층이 자기 정보를 헤더로 앞에 붙인다.**

```
응용 계층:   [ 위치 데이터 ]
                  │ TCP 헤더(포트 번호 등)를 앞에 붙임
                  ↓
전송 계층:   [ TCP헤더 | 위치 데이터 ]
                  │ IP 헤더(목적지 IP 등)를 앞에 붙임
                  ↓
인터넷 계층: [ IP헤더 | TCP헤더 | 위치 데이터 ]
                  │ 이더넷 헤더(MAC 주소 등)를 앞에 붙임
                  ↓
네트워크 접근: [ 이더넷헤더 | IP헤더 | TCP헤더 | 위치 데이터 ]
                  ↓
              실제 전선으로 전송 →→→
```

택배로 치면, 물건을 상자에 넣고(응용), 그 상자에 송장을 붙이고(전송), 송장 위에 지역 분류 스티커를 붙이고(인터넷), 트럭에 분류표를 다는(네트워크) 식이다. 받는 쪽은 **반대로** 한 겹씩 벗기면서 올라간다(역캡슐화).

이 구조 덕분에 각 층은 윗층/아랫층이 뭘 하는지 몰라도 자기 일만 하면 된다. 게임 코드는 "위치 데이터"만 던지고, TCP가 알아서 포트를 붙이고, IP가 알아서 주소를 붙인다.

## 5. 코드로 체감해보기

언리얼에서 멀티플레이 변수 하나를 동기화하는 코드를 보자.

```cpp
// 이 한 줄이 "캡슐화 → 전송 → 역캡슐화" 전체를 일으킨다
UPROPERTY(Replicated)
FVector ServerCharacterLocation;

void AMyCharacter::GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const
{
    Super::GetLifetimeReplicatedProps(OutLifetimeProps);
    DOREPLIFETIME(AMyCharacter, ServerCharacterLocation);   // "이 변수 다른 클라들한테도 보내줘"
}
```

우리가 보는 건 `UPROPERTY(Replicated)` 한 줄이지만, 그 아래에서 벌어지는 일은:

1. 언리얼이 `ServerCharacterLocation`을 **바이트로 직렬화** (응용 계층)
2. 그걸 전송 프로토콜(언리얼은 기본 UDP 기반)에 실어서 **포트를 붙이고** (전송 계층)
3. 상대 클라의 **IP로 보낼 주소를 붙이고** (인터넷 계층)
4. 랜선/와이파이로 **실제 신호 전송** (물리 계층)
5. 상대 컴퓨터에서 **반대로 한 겹씩 벗겨서** 다시 `FVector`로 복원

**언리얼 엔진의 네트워크 코드가 두꺼운 이유가 이거다.** 게임 개발자는 `Replicated` 한 줄만 쓰지만, 엔진은 직렬화부터 패킷 전송, 유실 처리, 순서 보정까지 다 해준다. 그 안에서 뭐가 도는지 아는 게 이 시리즈의 목표다.

## 6. 흔한 오해

### 오해 1: "인터넷이랑 네트워크는 같은 말 아니야?"

네트워크는 **컴퓨터들이 연결된 것 전체**를 부르는 일반 용어다. 인터넷은 그 중 **전 세계 네트워크를 다 이어 붙인, 가장 큰 네트워크 하나**다. 회사 안에서만 도는 사내망(LAN)도 네트워크지만 인터넷은 아니다. PC방의 같은 랜에 묶인 컴퓨터끼리 하는 게임은 인터넷 없이도 된다.

### 오해 2: "데이터는 보내면 그냥 도착한다"

네트워크는 **신뢰할 수 없는 통로**가 기본이다. 패킷은 사라질 수 있고(유실), 순서가 뒤바뀔 수 있고, 늦게 올 수 있다. "보냈으니 도착했겠지"는 틀렸다. 도착을 보장하고 싶으면 TCP를, 속도를 위해 유실을 감수하면 UDP를 쓴다 (4~5강).

### 오해 3: "OSI 7계층은 실제로 그렇게 돌아간다"

OSI 7계층은 **개념을 설명하기 위한 참조 모델**이지, 실제 구현이 칼같이 7층으로 나뉜 건 아니다. 실제 인터넷은 TCP/IP 모델로 돈다. OSI는 "이런 역할들이 있다"는 지도라고 보면 된다. 면접에서 "OSI대로 구현돼 있나요?" 물으면 "참조 모델이고, 실제 구현은 TCP/IP"라고 답하면 된다.

### 오해 4: "계층을 나누면 느려지지 않나?"

헤더가 겹겹이 붙으니 약간의 오버헤드는 있다. 하지만 계층을 안 나누면, 와이파이용 코드와 랜선용 코드를 게임마다 따로 짜야 한다. 층을 나눈 덕분에 **전송 방식이 바뀌어도 윗층 코드는 그대로** 쓸 수 있다. 이 유연성이 약간의 오버헤드보다 훨씬 가치 있다.

## 7. 면접에서 나오면

**Q1. OSI 7계층을 설명해보세요.**
→ "네트워크 통신을 역할별로 7개 층으로 나눈 참조 모델입니다. 아래부터 물리, 데이터링크, 네트워크, 전송, 세션, 표현, 응용 계층이고요. 실무에서 가장 중요한 건 IP로 목적지 컴퓨터를 찾는 네트워크 계층과, TCP·UDP로 어느 프로그램에 전달할지 정하는 전송 계층입니다."

**Q2. OSI 모델과 TCP/IP 모델의 차이는 뭔가요?**
→ "OSI는 7계층으로 나눈 이론적 참조 모델이고, TCP/IP는 실제 인터넷이 동작하는 4계층 모델입니다. TCP/IP는 OSI의 상위 세 층(세션·표현·응용)을 응용 계층 하나로 묶고, 하위 두 층을 네트워크 접근 계층으로 묶은 형태라고 보면 됩니다."

**Q3. 캡슐화가 뭔가요?**
→ "데이터가 상위 계층에서 하위 계층으로 내려갈 때, 각 계층이 자기 제어 정보를 헤더로 앞에 붙이는 과정입니다. 전송 계층에선 TCP 헤더, 인터넷 계층에선 IP 헤더가 붙는 식이죠. 받는 쪽은 반대로 한 겹씩 벗기면서 올라가는데 이걸 역캡슐화라고 합니다."

**Q4. 계층을 나눠서 통신하는 이유가 뭔가요?**
→ "각 계층이 독립적으로 자기 역할만 담당하기 때문에, 한 계층의 구현이 바뀌어도 다른 계층은 영향을 안 받습니다. 예를 들어 전송 수단이 랜선에서 와이파이로 바뀌어도 상위 계층 코드는 그대로 쓸 수 있죠. 유지보수와 표준화에 유리합니다."

**Q5. 프로토콜이 뭔가요?**
→ "통신하는 양쪽이 데이터를 어떤 형식으로, 어떤 순서로 주고받을지 정해놓은 약속입니다. 서로 다른 제조사의 장비들이 함께 동작할 수 있는 건 모두 같은 프로토콜을 따르기 때문입니다. 대표적으로 TCP, UDP, IP, HTTP 같은 게 있습니다."

면접관이 그 다음에 던지기 좋은 질문: *"그럼 전송 계층의 TCP와 UDP는 뭐가 다른가요?"* → Part 2(4~6강)에서 집중적으로 다룬다.
