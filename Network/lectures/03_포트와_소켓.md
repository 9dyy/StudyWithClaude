# 3강 — 포트와 소켓

> **목표:** 한 컴퓨터 안에서 여러 프로그램이 어떻게 각자 자기 패킷만 받는지(포트), 그리고 "소켓"이 정확히 뭔지 이해한다.
> **선수 지식:** 2강(IP 주소). IP가 "어느 컴퓨터"까지 정한다는 걸 알고 있어야 함.

---

## 1. IP만으론 부족하다

내 PC에서 지금 동시에 도는 것들을 보자.

- 게임 클라이언트 (서버랑 통신 중)
- 크롬 (유튜브 보는 중)
- 디스코드 (음성 채팅 중)

이 셋 다 **같은 공인 IP** 하나를 쓴다. 우리 집 대표 주소가 하나니까. 그런데 게임 서버가 보낸 패킷이 우리 집에 도착했을 때, 공유기는 이걸 **크롬한테 줘야 할까, 게임한테 줘야 할까?**

```
게임 서버 → (우리 집 공인 IP 1.2.3.4로 패킷 도착) → ???
                                                  게임? 크롬? 디스코드?
```

IP는 "어느 컴퓨터"까지만 정한다. 그 컴퓨터 안의 **어느 프로그램**한테 줄지는 IP만으로는 모른다. 이걸 정하는 게 **포트(Port)** 다.

---

## 2. 포트 — 프로그램의 번호표

포트는 컴퓨터 안에서 **프로그램을 구분하는 번호**다. 1강의 계층으로 치면 4계층(전송 계층)에서 쓴다.

> **핵심 비유:** IP는 아파트 **동**, 포트는 **호수**다.
> "강남아파트(IP) 7777호(포트)" 라고 해야 정확히 한 집에 도달한다.
> 동만 알면 어느 집인지 모르고, 호수만 알면 어느 아파트인지 모른다.

포트 번호는 16비트, 즉 **0 ~ 65535** 까지 있다.

```
패킷이 도착하면 OS가 포트 번호를 보고 분배:

1.2.3.4 : 7777  → 게임 클라이언트
1.2.3.4 : 50123 → 크롬 (유튜브 탭)
1.2.3.4 : 50124 → 디스코드
   ↑        ↑
  IP       포트
(어느 PC)  (어느 프로그램)
```

각 프로그램은 자기 포트를 "내 거"라고 OS에 등록(bind)해두고, OS는 그 포트로 온 패킷만 해당 프로그램에 넘긴다.

### Well-known 포트 (외워두면 좋은 것)

0~1023번은 정해진 용도로 예약돼 있다. 면접에 가끔 나온다.

| 포트 | 용도 |
|------|------|
| 80 | HTTP (웹) |
| 443 | HTTPS (보안 웹) |
| 53 | DNS |
| 22 | SSH |

게임은 보통 이 예약 구간을 피해서 `7777`, `27015` 같은 높은 번호를 쓴다. 언리얼 기본 게임 포트가 `7777`이다.

---

## 3. 소켓 — 통신의 손잡이

여기서 면접에 자주 나오는 단어가 등장한다. **소켓(Socket)**.

소켓은 **"IP + 포트" 한 쌍으로 만들어지는, 네트워크 통신의 끝점(endpoint)** 이다. 프로그램이 네트워크로 데이터를 주고받으려면 이 소켓이라는 손잡이를 통해서 한다.

```
소켓 = IP 주소 + 포트 번호

내 게임 클라:  192.168.0.5 : 50200   ← 이게 내 쪽 소켓
게임 서버:     203.0.113.10 : 7777   ← 이게 서버 쪽 소켓

이 두 소켓을 잇는 게 "연결(connection)"
```

프로그래머 입장에서 소켓은 **파일 핸들처럼 다루는 통신 창구**다. OS가 소켓을 하나 만들어서 번호(핸들)를 주면, 우리는 거기에 "써라(send)", "읽어라(recv)" 하고 명령한다. 파일에 쓰고 읽는 거랑 똑같은 모양이다.

> **OS 강의와 연결:** 소켓은 OS가 관리하는 자원이다. 파일 디스크립터처럼 소켓도 OS가 핸들로 관리한다. 그래서 다 쓰면 닫아줘야 한다(`close`). 안 닫으면 누수된다.

### 연결은 4개 값으로 식별된다

서버 입장에서 보자. 클라이언트 100명이 다 같은 서버 포트 `7777`로 접속한다. 그럼 서버는 누가 누군지 어떻게 구분할까?

연결 하나는 **4개 값(4-tuple)** 으로 유일하게 식별된다.

```
( 출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트 )

플레이어A: (1.1.1.1, 50200, 203.0.113.10, 7777)
플레이어B: (2.2.2.2, 51000, 203.0.113.10, 7777)
            └─ 클라마다 IP/포트가 달라서 ─┘
            서버 포트는 같아도 연결은 구분된다
```

이게 **"서버 하나가 어떻게 수천 명을 동시에 받느냐"** 의 답이다. 서버는 포트 하나(7777)로 듣고 있지만, 접속해오는 클라마다 IP·포트 조합이 다르니 연결은 전부 구분된다.

---

## 4. 그림으로 보면

```
                 게임 서버
           203.0.113.10 : 7777   ← 듣는 포트는 하나
                    │
        ┌───────────┼───────────┐
      연결A        연결B        연결C
        │            │            │
 1.1.1.1:50200  2.2.2.2:51000  3.3.3.3:49888
        │            │            │
    플레이어A     플레이어B     플레이어C
```

서버는 포트 7777 하나로 듣지만, 클라마다 소켓(IP:포트)이 달라서 동시에 여러 연결을 유지한다.

---

## 5. 코드로 체감해보기

언리얼에서 소켓을 직접 만지는 일은 드물지만(엔진이 가려줌), 개념을 보려면 이렇게 생겼다.

```cpp
// 소켓 하나 생성 — OS에 "통신 창구 하나 줘" 요청
FSocket* Socket = ISocketSubsystem::Get(PLATFORM_SOCKETSUBSYSTEM)
    ->CreateSocket(NAME_Stream, TEXT("MySocket"), false);
//                 ↑ NAME_Stream = TCP용 (다음 강의에서 다룸)

// 목적지 주소(소켓 끝점) 구성: IP + 포트
TSharedRef<FInternetAddr> ServerAddr =
    ISocketSubsystem::Get(PLATFORM_SOCKETSUBSYSTEM)->CreateInternetAddr();
bool bValid;
ServerAddr->SetIp(TEXT("203.0.113.10"), bValid);   // 어느 컴퓨터 (IP)
ServerAddr->SetPort(7777);                          // 어느 프로그램 (포트)

// 연결 시도 — 내 소켓과 서버 소켓을 잇는다
bool bConnected = Socket->Connect(*ServerAddr);

// 다 쓰면 반드시 닫기 (OS 자원 해제)
Socket->Close();
ISocketSubsystem::Get(PLATFORM_SOCKETSUBSYSTEM)->DestroySocket(Socket);
```

여기서 핵심은 **소켓을 만들 때 "어느 컴퓨터(IP) + 어느 프로그램(포트)"를 둘 다 지정**한다는 거다. 둘 중 하나라도 없으면 통신이 성립 안 한다.

> 실무에서 클라 개발자가 이 raw 소켓 코드를 직접 쓰는 일은 거의 없다. 보통 언리얼 `Replication`(14강)이나 HTTP 모듈(11강)을 쓴다. 다만 "그 아래에서 소켓이 이렇게 돈다"는 건 알아야 면접에서 막히지 않는다.

## 6. 흔한 오해

### 오해 1: "포트는 물리적인 구멍이다"

USB 포트, 랜선 꽂는 포트 같은 **물리 포트**랑 헷갈리기 쉽다. 네트워크에서 말하는 포트는 **소프트웨어상의 논리 번호**다. 물리적으로 존재하는 게 아니라, OS가 패킷을 어느 프로그램에 줄지 구분하려고 쓰는 숫자다.

### 오해 2: "한 포트는 한 연결만 쓸 수 있다"

서버는 포트 하나(예: 7777)로 **수천 개의 연결**을 동시에 처리한다. 연결은 포트 하나가 아니라 4-tuple(출발지IP·포트 + 목적지IP·포트)로 구분되기 때문이다. "포트 하나 = 연결 하나"는 틀렸다.

### 오해 3: "소켓이랑 포트는 같은 말이다"

포트는 **번호**고, 소켓은 **IP+포트로 만들어진 통신 끝점(객체)** 이다. 소켓이 포트를 포함한다. 소켓은 우리가 `send`/`recv` 하는 실제 손잡이고, 포트는 그 손잡이를 식별하는 번호 중 하나다.

### 오해 4: "소켓은 닫을 필요 없다"

소켓은 OS 자원이다. 안 닫으면 파일 핸들 누수처럼 쌓인다. 서버에서 연결 끊긴 소켓을 안 닫으면 시간이 지나며 "더 이상 소켓을 못 만드는" 상태가 된다. 반드시 닫아야 한다.

## 7. 면접에서 나오면

**Q1. 포트가 뭔가요?**
→ "한 컴퓨터 안에서 프로그램을 구분하는 16비트 번호입니다. IP가 어느 컴퓨터인지 정한다면, 포트는 그 컴퓨터의 어느 프로그램으로 데이터를 보낼지를 정합니다. 0부터 65535까지 있고, 0~1023은 HTTP의 80, HTTPS의 443처럼 용도가 정해진 well-known 포트입니다."

**Q2. 소켓이 뭔가요?**
→ "네트워크 통신의 끝점으로, IP 주소와 포트 번호 한 쌍으로 만들어집니다. 프로그램은 이 소켓을 통해 데이터를 보내고 받는데, 파일 핸들처럼 OS가 관리하는 자원이라 다 쓰면 닫아줘야 합니다."

**Q3. IP와 포트와 소켓의 관계를 설명해보세요.**
→ "IP는 어느 컴퓨터, 포트는 그 안의 어느 프로그램을 가리키고, 이 둘을 합친 통신 끝점이 소켓입니다. 아파트로 치면 IP가 동, 포트가 호수, 소켓이 그 집의 현관문 정도입니다."

**Q4. 서버 하나가 어떻게 수천 명의 클라이언트를 동시에 처리하나요?**
→ "서버는 포트 하나로 듣지만, 연결은 출발지 IP·포트와 목적지 IP·포트, 이 네 개 값의 조합으로 구분됩니다. 클라이언트마다 IP나 포트가 다르기 때문에, 서버 포트가 같아도 각 연결은 고유하게 식별돼서 동시에 여러 연결을 유지할 수 있습니다."

**Q5. well-known 포트를 아는 대로 말해보세요.**
→ "HTTP가 80번, HTTPS가 443번, DNS가 53번, SSH가 22번입니다. 0번부터 1023번까지가 이런 시스템 예약 포트라서, 게임 같은 일반 애플리케이션은 그 위의 번호, 예를 들어 7777번 같은 걸 씁니다."

면접관이 그 다음에 던지기 좋은 질문: *"소켓을 만들 때 TCP랑 UDP를 고르던데, 둘은 뭐가 다른가요?"* → 4강(TCP)·5강(UDP)에서 본격적으로 다룬다.

---

## 8. 셀프 체크

- [ ] IP만으로 부족하고 포트가 왜 필요한지 설명할 수 있다.
- [ ] 포트 번호 범위(0~65535)와 well-known 포트 몇 개를 안다.
- [ ] 소켓이 "IP+포트 끝점"이라는 걸 한 문장으로 말할 수 있다.
- [ ] 연결이 4-tuple로 식별된다는 걸 이해했고, 그래서 서버가 수천 명을 받는 원리를 설명할 수 있다.
- [ ] 소켓이 OS 자원이라 닫아야 한다는 걸 안다.
