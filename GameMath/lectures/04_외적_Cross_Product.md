# 4강 — 외적 (Cross Product)

> **목표:** 외적이 계산하는 게 뭔지, 부호로 좌/우를 어떻게 판정하는지, 회전축을 어떻게 구하는지 이해한다.
> **선수 지식:** 1~3강 (벡터, 정규화, 내적).

---

## 1. 도입 — "적이 내 왼쪽에 있는지 오른쪽에 있는지" 어떻게 판단하나

내적은 "얼마나 같은 방향인가"를 알려준다. 하지만 이런 질문에는 답을 못 준다: **"적이 내 정면 기준으로 왼쪽에 있나, 오른쪽에 있나?"**

내적 값만으로는 좌/우를 구분할 수 없다 — 내적은 대칭이라(`A·B == B·A`), 방향의 "차이량"은 알려줘도 "어느 쪽으로 치우쳤는지"는 알려주지 않는다. 이걸 구분하려면 **외적(Cross Product)**이 필요하다.

```cpp
FVector ToEnemy = (EnemyLocation - MyLocation).GetSafeNormal();
FVector MyForward = GetActorForwardVector();

FVector CrossResult = FVector::CrossProduct(MyForward, ToEnemy);
// CrossResult.Z가 양수면 오른쪽, 음수면 왼쪽 (언리얼 좌표계 기준)
```

외적은 각도 대신 **"어느 쪽으로 꺾여 있는가"**와 **"두 벡터에 동시에 수직인 방향"**을 알려준다. 이 두 가지가 어떻게 게임 로직에 쓰이는지 이 강의에서 다룬다.

---

## 2. 개념 설명

### 2-1. 외적의 정의 — 내적과 다르게 결과가 벡터다

외적은 두 벡터로부터 **세 번째 벡터**를 만들어낸다. 공식은 이렇다.

```
A × B = (A.Y*B.Z - A.Z*B.Y,  A.Z*B.X - A.X*B.Z,  A.X*B.Y - A.Y*B.X)
```

```cpp
FVector A = FVector(1, 0, 0);
FVector B = FVector(0, 1, 0);

FVector Result = FVector::CrossProduct(A, B);   // (0, 0, 1)
```

내적이 "스칼라 하나"를 뱉는 것과 달리, 외적은 **벡터**를 뱉는다. 이게 가장 먼저 기억해야 할 차이다.

### 2-2. 외적 결과 벡터의 정체 — 두 벡터 모두에 수직인 벡터(법선)

외적 결과 벡터는 **원래 두 벡터가 이루는 평면에 수직인 벡터**다. 이걸 **법선 벡터(Normal Vector)**라고 부른다.

```
A × B 는 A에도 수직, B에도 수직이다.
```

방금 예시에서 `A=(1,0,0)`(X축), `B=(0,1,0)`(Y축)이고, 이 둘이 이루는 평면(XY 평면)에 수직인 축은 Z축이다. 그래서 결과가 `(0,0,1)`, 즉 Z축 방향으로 나온 것이다.

**법선 벡터가 게임에서 쓰이는 대표적인 곳: 지형/바닥의 기울기.** 바닥이 평평한지 경사졌는지는 그 표면의 법선 벡터가 얼마나 위(Z축)를 향하는지로 판단한다. 캐릭터 무브먼트 컴포넌트가 "이 경사는 걸을 수 있다/없다"를 판단할 때 내부적으로 이 법선 벡터와 내적을 조합해서 쓴다.

### 2-3. 외적의 순서가 중요하다 — 반교환 법칙

내적은 `A·B == B·A`지만, 외적은 **순서를 바꾸면 결과가 반대 방향**이 된다.

```
A × B = -(B × A)
```

```cpp
FVector Forward1 = FVector::CrossProduct(A, B);   // 예: (0,0,1)
FVector Forward2 = FVector::CrossProduct(B, A);   // (0,0,-1) — 정반대
```

이게 바로 좌/우 판정의 핵심이다. `CrossProduct(MyForward, ToEnemy)`와 `CrossProduct(ToEnemy, MyForward)`는 부호가 정반대로 나온다. 어느 벡터를 먼저 넣느냐에 따라 "왼쪽=양수/오른쪽=음수"인지 그 반대인지가 결정되므로, 프로젝트 안에서 순서를 일관되게 정해놓고 써야 한다.

### 2-4. 외적의 크기 — 사인(sin) 값과 평행사변형 넓이

내적의 크기가 `cos(θ)`와 연결되듯, 외적 결과 벡터의 **크기**는 `sin(θ)`와 연결된다.

```
|A × B| = |A| * |B| * sin(θ)
```

이 값은 기하학적으로 **A와 B가 만드는 평행사변형의 넓이**와 같다. 두 벡터가 평행(θ=0 또는 180도)이면 `sin(θ)=0`이라 외적 결과가 0벡터가 된다는 것도 여기서 자연스럽게 나온다 — "평행한 두 벡터는 법선(수직 방향)을 정의할 수 없다"는 것과 같은 말이다.

### 2-5. 언리얼에서 좌/우 판정하기

캐릭터 정면 기준으로 목표가 왼쪽인지 오른쪽인지 판정할 때는, 결과 벡터 전체가 아니라 **Z 성분의 부호**만 보면 된다(캐릭터가 대체로 지면과 수평으로 움직인다고 가정할 때).

```cpp
float ELocalizedSide(AActor* Self, AActor* Target)
{
    FVector Forward = Self->GetActorForwardVector();
    FVector ToTarget = (Target->GetActorLocation() - Self->GetActorLocation()).GetSafeNormal();

    FVector Cross = FVector::CrossProduct(Forward, ToTarget);

    // 언리얼 좌표계(왼손, Z-up) 기준: Z가 양수면 오른쪽, 음수면 왼쪽
    return Cross.Z;   // 양수: 오른쪽, 음수: 왼쪽, 0에 가까움: 정면/후방
}
```

부호만 필요하다면 굳이 벡터 전체를 정규화할 필요도 없다 — 부호는 크기와 무관하게 결정되기 때문이다. (단, 크기까지 의미 있게 쓰려면 앞서 본 것처럼 정규화가 필요하다.)

### 2-6. 법선 벡터로 "걸을 수 있는 경사인지" 판정하기

2-2에서 외적 결과가 법선 벡터(두 벡터가 이루는 평면에 수직인 벡터)라고 했는데, 이게 실제로 쓰이는 대표 사례가 **경사면이 걸을 수 있는 각도인지 판정**하는 것이다. 언리얼 캐릭터 무브먼트 컴포넌트의 `WalkableFloorAngle`이 내부적으로 이 계산을 한다.

바닥 삼각형의 두 변을 외적하면 그 바닥의 법선 벡터가 나온다. 이 법선 벡터와 월드 Up 벡터 `(0,0,1)`을 **내적(3강)**하면, 그 값이 곧 바닥 기울기 각도의 코사인이 된다.

```cpp
bool IsFloorWalkable(const FVector& FloorNormal, float MaxWalkableAngleDegrees)
{
    // 법선이 위(Up)를 향할수록 평평한 바닥, 옆을 향할수록 가파른 경사/벽
    float DotWithUp = FVector::DotProduct(FloorNormal.GetSafeNormal(), FVector::UpVector);
    float MaxCos = FMath::Cos(FMath::DegreesToRadians(MaxWalkableAngleDegrees));

    return DotWithUp >= MaxCos;   // 3강의 시야각 판정과 정확히 같은 형태
}
```

외적으로 법선을 구하고, 내적으로 그 법선의 기울기를 판정한다 — 이 강의와 3강이 실제 언리얼 엔진 내부에서 어떻게 손을 잡고 쓰이는지 보여주는 예시다.

## 3. 그림으로 보면

```
              Z (위쪽, 화면 밖으로)
              │
              │
  Forward ────┼──────→ ToTarget이 오른쪽에 있으면
              │          Cross(Forward, ToTarget)는 +Z 방향
              │
        (왼손 좌표계 기준)

  평행사변형 넓이 = |A × B|

     A ────────────╲
    ╱                ╲
   ╱   넓이 = |A×B|    ╲
  ╱______________________╲
                          B
```

## 4. 코드로 — 실제 사례: 좌우 회피(Dodge) 방향 결정

플레이어가 공격받았을 때, 공격자 기준으로 어느 쪽으로 피해야 더 안전한지 판단하는 로직이다.

```cpp
FVector AMyCharacter::GetDodgeDirection(AActor* Attacker) const
{
    FVector AttackerForward = Attacker->GetActorForwardVector();
    FVector AttackerToMe = (GetActorLocation() - Attacker->GetActorLocation()).GetSafeNormal();

    FVector Cross = FVector::CrossProduct(AttackerForward, AttackerToMe);

    // 공격자 기준 내가 오른쪽에 있으면, 더 바깥쪽인 오른쪽으로 회피
    FVector RightVector = GetActorRightVector();
    return (Cross.Z >= 0.0f) ? RightVector : -RightVector;
}
```

이 판정 하나로 "공격 범위 밖으로 더 짧은 경로로 피하기" 같은 AI 회피 로직의 뼈대를 만들 수 있다.

## 5. 흔한 오해

### 오해 1: "외적도 내적처럼 스칼라 하나가 나온다"

외적의 결과는 **벡터**다. 다만 좌/우 판정처럼 부호만 필요할 때는 결과 벡터의 특정 성분(주로 Z)만 뽑아 쓰기 때문에 스칼라처럼 느껴질 뿐이다.

### 오해 2: "A×B와 B×A는 같은 결과다"

외적은 교환법칙이 성립하지 않는다. `A×B = -(B×A)`로 **정반대 방향**이 나온다. 좌/우 판정에서 인자 순서를 바꾸면 결과가 뒤집힌다는 걸 꼭 기억해야 한다.

### 오해 3: "두 벡터가 평행하면 외적도 뭔가 의미 있는 방향이 나온다"

두 벡터가 평행(또는 한쪽이 0벡터)이면 외적 결과는 **0벡터**다. 평행한 두 벡터로는 "이 평면에 수직인 방향"이라는 게 정의되지 않기 때문이다.

### 오해 4: "외적 결과 벡터를 그대로 방향으로 쓰면 된다"

외적 결과 벡터의 크기는 `|A||B|sin(θ)`라서 A, B의 크기와 각도에 따라 제각각이다. 방향만 필요하면(예: 회전축) 반드시 정규화해서 써야 한다.

### 오해 5: "좌/우 판정은 항상 Z 성분을 보면 된다"

이건 캐릭터가 XY 평면(지면)에서 대체로 수평으로 움직인다고 가정할 때만 성립한다. 비행체처럼 3차원으로 자유롭게 회전하는 오브젝트라면 단순히 Z 성분만 봐서는 안 되고, 외적 결과 벡터와 오브젝트의 실제 Up 벡터를 내적해서 부호를 판단해야 한다.

## 6. 면접에서 나오면

**Q1. 외적이 뭔가요?**
→ "두 벡터로부터 그 두 벡터 모두에 수직인 새로운 벡터를 만드는 연산입니다. 내적은 결과가 스칼라지만 외적은 결과가 벡터라는 게 가장 큰 차이입니다."

**Q2. 외적으로 좌/우를 어떻게 판정하나요?**
→ "캐릭터의 정면 벡터와 타겟 방향 벡터를 외적하면, 결과 벡터의 특정 축(언리얼 기준 Z축) 부호로 타겟이 왼쪽에 있는지 오른쪽에 있는지 판정할 수 있습니다. 부호가 양수면 오른쪽, 음수면 왼쪽입니다."

**Q3. 외적에서 A×B와 B×A는 같은가요?**
→ "아니요, 방향이 정반대입니다. 외적은 교환법칙이 성립하지 않아서 A×B = -(B×A)입니다. 그래서 좌우 판정할 때 인자 순서를 실수하면 결과가 뒤집힙니다."

**Q4. 외적 결과 벡터의 크기는 뭘 의미하나요?**
→ "두 벡터가 이루는 각도의 사인 값에 두 벡터 크기를 곱한 값이고, 기하학적으로는 두 벡터가 만드는 평행사변형의 넓이와 같습니다."

**Q5. 두 벡터가 평행하면 외적 결과는 어떻게 되나요? 왜 그런가요?**
→ "0벡터가 나옵니다. sin(0도)나 sin(180도)가 0이기 때문이고, 직관적으로도 평행한 두 벡터로는 수직인 방향이 유일하게 정해지지 않기 때문입니다."

**Q6. 회전축을 구할 때 왜 외적을 쓰나요?**
→ "두 방향 벡터 사이를 회전시키려면, 그 두 벡터가 이루는 평면에 수직인 축을 기준으로 돌려야 하는데, 그 축을 구하는 게 정확히 외적이 하는 일이기 때문입니다. 예를 들어 현재 정면 벡터에서 목표 방향 벡터로 회전시킬 때 회전축을 외적으로 구합니다."

**Q7. 내적과 외적 중 어떤 걸 언제 쓰는지 설명해주세요.**
→ "'얼마나 같은 방향인가', '정면 시야각 안에 있는가'처럼 각도의 크기 자체가 중요할 때는 내적을 씁니다. '어느 쪽으로 치우쳤는가', '회전축이 뭔가'처럼 방향의 부호나 수직 방향이 필요할 때는 외적을 씁니다."

## 7. 셀프 체크

- [ ] 외적의 결과가 벡터라는 것과, 그 벡터가 두 원래 벡터 모두에 수직이라는 걸 안다.
- [ ] 외적의 순서를 바꾸면 결과가 반대 방향이 된다는 걸(반교환 법칙) 설명할 수 있다.
- [ ] 외적으로 좌/우 판정 로직을 짤 수 있다.
- [ ] 외적 결과 벡터의 크기가 sin(θ) 및 평행사변형 넓이와 연결된다는 걸 안다.
- [ ] 두 벡터가 평행할 때 외적이 0벡터가 되는 이유를 설명할 수 있다.
- [ ] 내적과 외적을 각각 언제 써야 하는지 구분할 수 있다.
