# 7강 — 충돌 감지 기초

> **목표:** AABB와 구체 충돌 판정을 직접 계산할 수 있고, 브로드 페이즈/내로우 페이즈가 왜 나뉘는지 설명할 수 있다.
> **선수 지식:** 1~6강 (벡터, 정규화, 내적, 외적, 좌표계, Look-At).

---

## 1. 도입 — 총알이 벽에 맞았는지 매 프레임 어떻게 확인하나

총알(Projectile)이 날아가다가 벽에 부딪히면 사라지고 이펙트를 재생해야 한다. 이걸 코드로 짜려면 "이 두 오브젝트가 겹쳤는가?"를 매 프레임 계산해야 하는데, 게임 오브젝트는 대개 구체, 박스, 캡슐처럼 단순한 도형이 아니라 복잡한 메시(Mesh)다.

메시의 정확한 삼각형 단위로 충돌을 매 프레임 계산하면 너무 느리다. 그래서 실제로는 **충돌 감지 전용으로 단순화된 도형**(Collision Shape)을 따로 두고, 그 단순한 도형끼리 겹쳤는지를 계산한다. 언리얼 에디터에서 메시에 캡슐이나 박스 모양의 초록색 콜리전이 따로 붙어있는 걸 본 적 있을 텐데, 그게 바로 이거다.

이 강의는 그 "단순화된 도형끼리 겹쳤는가"를 실제로 어떻게 계산하는지 다룬다.

---

## 2. 개념 설명

### 2-1. 구체(Sphere) 충돌 — 가장 싸고 단순한 판정

두 구체가 겹쳤는지는 "중심 사이 거리가 두 반지름의 합보다 작은가"만 확인하면 된다.

```
겹침 여부 = Distance(CenterA, CenterB) <= RadiusA + RadiusB
```

```cpp
bool IsSphereOverlapping(const FVector& CenterA, float RadiusA,
                          const FVector& CenterB, float RadiusB)
{
    // 2강에서 배운 대로, 단순 비교는 sqrt 없이 제곱 거리로
    float DistSquared = FVector::DistSquared(CenterA, CenterB);
    float RadiusSum = RadiusA + RadiusB;
    return DistSquared <= RadiusSum * RadiusSum;
}
```

`DistSquared`를 쓰고 반지름 합도 제곱해서 비교하는 이유는 2강에서 이미 다뤘다 — 대소 비교만 할 거면 `sqrt` 호출을 아낄 수 있다. 구체 충돌은 계산량이 가장 적어서, 폭발 범위 판정이나 대략적인 근접 판정에 자주 쓰인다.

### 2-2. AABB(Axis-Aligned Bounding Box) 충돌

AABB는 "축에 정렬된 바운딩 박스" — 회전 없이 X, Y, Z축에 딱 맞춰진 직육면체다. 각 박스를 최소점(Min)과 최대점(Max) 두 좌표로 표현한다.

```cpp
struct FAABB
{
    FVector Min;
    FVector Max;
};

bool IsAABBOverlapping(const FAABB& A, const FAABB& B)
{
    // 세 축 모두 겹쳐야 전체가 겹친 것
    bool bOverlapX = A.Min.X <= B.Max.X && A.Max.X >= B.Min.X;
    bool bOverlapY = A.Min.Y <= B.Max.Y && A.Max.Y >= B.Min.Y;
    bool bOverlapZ = A.Min.Z <= B.Max.Z && A.Max.Z >= B.Min.Z;
    return bOverlapX && bOverlapY && bOverlapZ;
}
```

핵심 아이디어: **3차원 충돌 판정을 축 3개의 독립적인 1차원 겹침 판정으로 쪼갠다.** 한 축이라도 안 겹치면 두 박스는 절대 겹칠 수 없다(그 축 방향으로 완전히 떨어져 있다는 뜻이므로). 이 "각 축을 따로 검사한다"는 아이디어는 뒤에 나올 SAT(분리축 정리)로 이어지는 기본 발상이다.

AABB는 회전을 반영하지 못한다는 한계가 있다 — 오브젝트가 45도 회전해도 AABB는 여전히 축 정렬 상태로, 실제 형태보다 넉넉하게(혹은 다르게) 잡힌다. 그래서 정밀한 충돌보다는 **1차 필터링용**으로 많이 쓰인다.

### 2-3. 브로드 페이즈 vs 내로우 페이즈

레벨에 오브젝트가 1,000개 있다고 하면, 모든 쌍(약 50만 쌍)을 정밀하게 검사하는 건 너무 비싸다. 그래서 물리 엔진은 충돌 검사를 두 단계로 나눈다.

| 단계 | 목적 | 특징 |
|------|------|------|
| **브로드 페이즈(Broad Phase)** | "겹칠 가능성이 있는 쌍"을 빠르게 걸러냄 | AABB처럼 싸고 단순한 도형으로 대략적 필터링. 공간 분할(그리드, BVH 등) 활용 |
| **내로우 페이즈(Narrow Phase)** | 브로드 페이즈를 통과한 쌍만 정밀 검사 | 실제 메시 형태, 정확한 충돌 지점, 충돌 법선까지 계산 |

```
1000개 오브젝트
      │
      ▼
[브로드 페이즈] AABB로 대략 겹치는 쌍만 추림 (예: 50쌍)
      │
      ▼
[내로우 페이즈] 그 50쌍만 정밀 충돌 검사 (실제 메시/캡슐 기준)
      │
      ▼
실제 충돌 이벤트 발생
```

이게 왜 필요한지는 계산량으로 보면 명확하다. 모든 쌍(N개면 N² 규모)을 정밀 검사하는 대신, 싼 연산(AABB 비교)으로 대부분을 미리 걸러내고 비싼 연산(정밀 충돌)은 살아남은 소수에만 적용하는 것이다. 언리얼의 물리 엔진(Chaos)도 내부적으로 이 2단계 구조를 쓴다 — `bGenerateOverlapEvents`, 콜리전 채널 설정이 이 파이프라인에 관여하는 설정들이다.

### 2-4. 콜리전 채널 — "누구와 부딪힐 것인가"를 미리 정하는 규칙

모든 오브젝트가 서로 다 부딪히면 곤란하다 — 총알이 다른 총알끼리 충돌하거나, 트리거 볼륨이 물리적으로 캐릭터를 막아버리면 안 된다. 언리얼은 **콜리전 채널**(Pawn, WorldStatic, Projectile 등)과 **응답 규칙**(Block/Overlap/Ignore)으로 "이 채널과 저 채널이 만나면 어떻게 반응할지"를 미리 정의해둔다.

```cpp
// 총알은 Pawn과는 Overlap(겹침만 감지), WorldStatic과는 Block(막힘)
Projectile->GetCollisionComponent()->SetCollisionResponseToChannel(
    ECC_Pawn, ECollisionResponse::ECR_Overlap);
Projectile->GetCollisionComponent()->SetCollisionResponseToChannel(
    ECC_WorldStatic, ECollisionResponse::ECR_Block);
```

이 규칙 자체가 충돌 계산량을 줄여주는 또 다른 축이다 — Ignore로 설정된 채널 쌍은 애초에 브로드 페이즈에서부터 검사 대상에서 제외된다.

### 2-5. 빠른 총알이 벽을 뚫고 지나간다 — 터널링(Tunneling)과 CCD

매 프레임 위치를 갱신하는 방식으로 충돌을 검사하면, **한 프레임에 이동하는 거리가 벽 두께보다 크면** 총알이 벽 안쪽과 바깥쪽 어디에도 걸리지 않고 그냥 통과해버리는 문제가 생긴다. 이걸 **터널링(Tunneling)**이라고 부른다. 저격총처럼 초고속 투사체를 만들 때 실제로 자주 부딪히는 문제다.

```
프레임 N:   ● (벽 앞)         ┃벽┃
프레임 N+1:                   ┃벽┃         ● (벽 뒤, 벽을 통과해버림!)
```

이 문제의 해결책이 **연속 충돌 감지(CCD, Continuous Collision Detection)**다. 단순히 "이번 프레임의 최종 위치"만 검사하는 대신, **이전 프레임 위치에서 이번 프레임 위치까지 이어지는 경로 전체**를 라인 트레이스나 스윕(Sweep) 검사로 훑어서 그 사이에 뭔가와 부딪혔는지 확인한다.

```cpp
// 단순 위치 검사(터널링 위험) 대신, 이전 위치 → 현재 위치 구간을 스윕 검사
FHitResult HitResult;
bool bHit = GetWorld()->SweepSingleByChannel(
    HitResult,
    PreviousLocation,      // 이전 프레임 위치
    NewLocation,           // 이번 프레임 위치
    FQuat::Identity,
    ECC_WorldStatic,
    FCollisionShape::MakeSphere(ProjectileRadius));

if (bHit)
{
    NewLocation = HitResult.Location;   // 실제 충돌 지점에서 멈춤
    OnProjectileHit(HitResult);
}
```

언리얼의 `ProjectileMovementComponent`에는 `bSweepCollision`(경로 전체를 스윕 검사할지) 옵션이 있는데, 이게 바로 이 CCD 개념을 켜고 끄는 스위치다. 다만 스윕 검사는 단순 위치 비교보다 계산 비용이 크기 때문에, 느리게 움직이는 오브젝트에까지 전부 켜두면 불필요한 성능 낭비가 된다 — 빠르게 움직이는 오브젝트(투사체, 총알)에만 선택적으로 켜는 게 일반적이다.

```
구체 충돌:                        AABB 충돌:

   ○ A (반지름 rA)              ┌────┐
    ＼                          │ A  │┌────┐
     ＼ d                       └────┼┤ B  │
      ＼                             └┴────┘
       ○ B (반지름 rB)          (X축, Y축 둘 다 겹쳐야 충돌)

  d <= rA + rB → 충돌            모든 축 Overlap → 충돌
```

## 4. 코드로 — 실제 사례: 간단한 폭발 범위 데미지

```cpp
void AExplosive::ApplyExplosionDamage()
{
    TArray<AActor*> OverlappingActors;
    UGameplayStatics::GetAllActorsOfClass(GetWorld(), APawn::StaticClass(), OverlappingActors);

    for (AActor* Actor : OverlappingActors)
    {
        // 브로드 페이즈에 해당: 일단 싼 구체 충돌로 후보를 거른다
        float DistSquared = FVector::DistSquared(GetActorLocation(), Actor->GetActorLocation());
        if (DistSquared > ExplosionRadius * ExplosionRadius)
        {
            continue;   // 범위 밖이면 스킵
        }

        // 여기서부터가 내로우 페이즈에 해당: 실제 라인 트레이스로 벽에 가려졌는지 정밀 검사
        FHitResult HitResult;
        bool bBlocked = GetWorld()->LineTraceSingleByChannel(
            HitResult, GetActorLocation(), Actor->GetActorLocation(), ECC_Visibility);

        if (!bBlocked)
        {
            UGameplayStatics::ApplyDamage(Actor, ExplosionDamage, nullptr, this, nullptr);
        }
    }
}
```

싼 구체 거리 체크로 대부분의 액터를 먼저 걸러내고, 살아남은 소수에만 비싼 라인 트레이스를 적용하는 것 자체가 브로드/내로우 페이즈 아이디어를 그대로 실무 코드에 옮긴 것이다.

## 5. 흔한 오해

### 오해 1: "충돌 판정은 항상 실제 메시 형태로 정밀하게 계산된다"

정확도가 제일 중요한 순간(최종 충돌 확정)에만 정밀 계산을 하고, 그 전 단계(브로드 페이즈)에서는 훨씬 단순한 도형(AABB, 구체)으로 후보를 추려낸다. 매 프레임 모든 오브젝트 쌍을 메시 단위로 검사하면 성능이 감당이 안 된다.

### 오해 2: "AABB는 회전한 오브젝트에도 그대로 잘 맞는다"

AABB는 이름 그대로 축에 정렬(Axis-Aligned)되어 있어서, 오브젝트가 회전해도 박스 자체는 회전하지 않는다. 회전한 오브젝트를 감싸려면 그 순간의 실제 형태를 다시 감싸는 새 AABB를 계산하거나, 회전을 반영하는 OBB(Oriented Bounding Box) 같은 다른 도형을 써야 한다.

### 오해 3: "구체 충돌이 제일 부정확하니까 안 쓰는 게 낫다"

정확도는 형태에 맞을 때 얘기고, 애초에 폭발 범위나 감지 범위처럼 "원형 범위"가 실제로 의미 있는 상황에서는 구체 충돌이 가장 자연스럽고 싸다. 오브젝트의 실제 형태(긴 직사각형 등)와 구체가 안 맞을 때만 문제가 된다.

### 오해 4: "콜리전 채널 설정은 성능과 무관하고 그냥 '부딪힐지 말지' 규칙일 뿐이다"

Ignore로 설정된 채널 쌍은 브로드 페이즈 단계에서부터 아예 검사 대상에서 빠지기 때문에, 콜리전 채널을 세밀하게 나누는 건 정확성뿐 아니라 성능에도 직접 영향을 준다. 불필요하게 모든 채널을 Block으로 켜두면 계산량이 그만큼 늘어난다.

### 오해 5: "매 프레임 위치만 비교하면 충돌은 다 잡힌다"

빠르게 움직이는 오브젝트는 한 프레임 이동 거리가 충돌 대상의 두께보다 커서, 위치 비교만으로는 그 사이를 통과해버린 걸 놓칠 수 있다(터널링). 이럴 땐 이전 위치부터 현재 위치까지의 경로 전체를 스윕 검사하는 CCD가 필요하다.

## 6. 면접에서 나오면

**Q1. 물체 간 충돌은 어떻게 감지하나요?**
→ "메시 원본 형태 대신 구체나 박스처럼 단순화된 콜리전 도형을 따로 두고, 그 도형끼리 겹쳤는지를 계산합니다. 구체는 중심 사이 거리와 반지름 합을 비교하고, 박스(AABB)는 각 축의 최소/최대값이 겹치는지를 확인합니다."

**Q2. 구체 충돌 판정은 구체적으로 어떻게 계산하나요?**
→ "두 구체 중심 사이의 거리가 두 반지름의 합보다 작거나 같으면 겹친 것으로 판정합니다. 성능을 위해 실제로는 거리를 제곱근 없이 제곱값끼리 비교합니다."

**Q3. AABB가 뭔가요?**
→ "Axis-Aligned Bounding Box의 줄임말로, 축에 정렬된 바운딩 박스입니다. 각 축의 최소, 최대 좌표로 표현하고, 세 축 모두 겹칠 때만 두 박스가 겹친 것으로 판정합니다."

**Q4. 브로드 페이즈와 내로우 페이즈가 왜 나뉘어 있나요?**
→ "오브젝트가 많을 때 모든 쌍을 정밀하게 검사하면 계산량이 너무 커지기 때문입니다. 먼저 AABB 같은 싼 연산으로 겹칠 가능성이 있는 쌍만 걸러내고(브로드 페이즈), 그 소수의 쌍만 실제 형태로 정밀 검사(내로우 페이즈)해서 전체 연산량을 줄입니다."

**Q5. 성능이 중요한 상황에서 구체 충돌과 AABB 충돌, 정밀 메시 충돌 중 어떤 걸 고르겠어요?**
→ "가능한 한 싼 도형부터 씁니다. 대략적인 범위 판정이면 구체나 AABB로 충분하고, 실제 화면에 보이는 정확한 충돌 지점이 필요한 마지막 단계에서만 정밀 충돌을 씁니다. 처음부터 정밀 메시 충돌을 전 오브젝트에 매 프레임 돌리는 건 낭비입니다."

**Q6. 콜리전 채널이 왜 필요한가요?**
→ "모든 오브젝트가 서로 다 부딪히면 안 되는 조합이 많기 때문입니다. 총알끼리는 안 부딪혀야 하고, 트리거 볼륨은 캐릭터를 물리적으로 막으면 안 되는 것처럼요. 채널별로 Block, Overlap, Ignore 응답을 정해두면 불필요한 충돌 계산 자체를 줄일 수 있습니다."

**Q7. AABB 충돌 판정 코드를 짜본다면 어떻게 하겠어요?**
→ "각 박스를 최소점과 최대점으로 표현하고, X, Y, Z축 각각에 대해 한쪽의 최소값이 다른 쪽의 최대값보다 작거나 같은지 비교합니다. 세 축 모두 겹쳐야만 전체 박스가 겹친 것으로 판정합니다."

**Q8. 빠른 총알이 벽을 뚫고 지나가는 문제를 어떻게 해결하나요?**
→ "터널링이라고 부르는 문제인데, 한 프레임 이동 거리가 벽 두께보다 커서 매 프레임 위치 비교로는 못 잡습니다. 이전 위치에서 현재 위치까지 경로 전체를 스윕 검사하는 연속 충돌 감지(CCD)를 적용해서 해결합니다. 다만 계산 비용이 있어서 빠르게 움직이는 오브젝트에만 선택적으로 켜는 게 일반적입니다."
> 면접관이 그 다음에 던지기 좋은 질문: "그럼 모든 오브젝트에 CCD를 켜두면 안 되나요?" → 스윕 검사가 단순 위치 비교보다 비싸서, 필요한 대상에만 선택적으로 적용해야 한다는 트레이드오프로 답하면 된다.

## 7. 셀프 체크

- [ ] 구체 충돌 판정 공식을 안다.
- [ ] AABB 충돌 판정이 축별 1차원 겹침 검사로 이뤄진다는 걸 설명할 수 있다.
- [ ] 브로드 페이즈와 내로우 페이즈가 왜 나뉘는지, 각각 뭘 하는지 안다.
- [ ] AABB의 한계(회전 미반영)를 설명할 수 있다.
- [ ] 콜리전 채널이 정확성뿐 아니라 성능에도 영향을 준다는 걸 안다.
- [ ] 터널링 문제가 왜 생기는지, CCD(스윕 검사)가 이걸 어떻게 해결하는지 설명할 수 있다.
