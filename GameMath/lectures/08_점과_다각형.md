# 8강 — 점과 다각형

> **목표:** 점이 다각형 내부에 있는지 판정하는 두 가지 방법(외적 부호, Winding Number)을 이해하고 구현할 수 있다.
> **선수 지식:** 1~7강 (벡터, 정규화, 내적, 외적, 좌표계, Look-At, 충돌 감지).

---

## 1. 도입 — 클릭한 지점이 이 구역 안에 있는지 어떻게 판정하나

RTS 게임에서 "이 사각형이 아니라 오각형 모양의 안전 구역 안에 마우스 클릭 지점이 들어왔는지" 판정해야 한다고 하자. 7강에서 배운 AABB나 구체로는 이런 임의의 다각형 모양을 표현할 수 없다.

이럴 때 필요한 게 **점-다각형 내부/외부 판정(Point-in-Polygon Test)**이다. 스킬 범위 표시, 존(Zone) 감지, 미니맵 상의 영역 클릭 판정처럼 사각형/원으로 딱 떨어지지 않는 영역을 다룰 때 자주 나온다.

```cpp
bool bIsInside = IsPointInPolygon(ClickedPoint, ZoneVertices);
```

이 강의는 이 판정을 실제로 어떻게 구현하는지, 대표적인 두 가지 방법(외적 부호 판정, Winding Number)을 다룬다.

---

## 2. 개념 설명

### 2-1. 볼록 다각형(Convex Polygon)에서의 외적 부호 판정

가장 직관적인 방법: 다각형의 각 변에 대해, 점이 그 변의 "안쪽"에 있는지를 4강에서 배운 **외적의 부호**로 확인한다.

**아이디어:** 다각형의 꼭짓점을 순서대로(반시계 방향이라고 하자) 돌면서, 각 변의 방향 벡터와 "그 변의 시작점에서 판정할 점까지의 벡터"를 외적한다. 모든 변에 대해 외적 부호가 **일관되게 같은 방향**이면, 점은 다각형 내부에 있다.

```cpp
bool IsPointInConvexPolygon2D(const FVector2D& Point, const TArray<FVector2D>& Vertices)
{
    int32 NumVertices = Vertices.Num();
    bool bHasPositive = false;
    bool bHasNegative = false;

    for (int32 i = 0; i < NumVertices; ++i)
    {
        FVector2D Edge = Vertices[(i + 1) % NumVertices] - Vertices[i];
        FVector2D ToPoint = Point - Vertices[i];

        // 2D 외적(스칼라 값): Edge.X * ToPoint.Y - Edge.Y * ToPoint.X
        float Cross = Edge.X * ToPoint.Y - Edge.Y * ToPoint.X;

        if (Cross > 0.0f) bHasPositive = true;
        if (Cross < 0.0f) bHasNegative = true;
    }

    // 모든 변에서 부호가 한쪽으로만 나오면(둘 다 나오지 않으면) 내부
    return !(bHasPositive && bHasNegative);
}
```

2D에서의 "외적"은 3D 외적의 Z 성분만 계산한 것과 같다 — 4강에서 본 `A × B`의 Z 성분 공식(`A.X*B.Y - A.Y*B.X`)을 그대로 쓴 것이다. 부호가 양수면 점이 변의 왼쪽, 음수면 오른쪽에 있다는 뜻이고(4강에서 좌/우 판정한 것과 정확히 같은 원리), **모든 변에 대해 같은 쪽에 있으면 다각형 안**이라는 논리다.

이 방법은 **볼록 다각형**(오목한 부분이 없는 다각형)에서만 정확하다. 오목 다각형에서는 변마다 "안쪽"의 의미가 뒤틀리기 때문에 이 단순한 부호 비교가 깨진다.

### 2-2. 오목 다각형까지 다루는 방법 — Ray Casting(레이 캐스팅)

오목 다각형도 처리하려면 다른 접근이 필요하다. **레이 캐스팅 방법**: 판정할 점에서 임의의 방향(보통 오른쪽 무한대)으로 광선을 쏴서, 그 광선이 다각형의 변과 **몇 번 교차하는지** 센다.

- 교차 횟수가 **홀수**면 점은 다각형 **내부**.
- 교차 횟수가 **짝수**면 점은 다각형 **외부**.

```
   ●─────────────────────→ (광선, 무한히 오른쪽으로)
   │
   점이 다각형 밖   교차 0번(짝수) → 외부
   점이 다각형 안   교차 1번(홀수) → 내부
   점이 오목한 부분 안 교차 3번(홀수) → 내부 (맞게 처리됨)
```

이 방법이 오목 다각형에서도 통하는 이유: 점에서 시작한 광선이 다각형 경계를 넘나들 때마다 "안/밖"이 뒤집힌다는 사실 자체는 다각형이 볼록이든 오목이든 항상 성립하기 때문이다. 몇 번 넘나들었는지(홀짝)만 세면 되므로, 다각형의 복잡한 모양과 무관하게 일반적으로 적용된다.

```cpp
bool IsPointInPolygonRayCast(const FVector2D& Point, const TArray<FVector2D>& Vertices)
{
    int32 NumVertices = Vertices.Num();
    bool bInside = false;

    for (int32 i = 0, j = NumVertices - 1; i < NumVertices; j = i++)
    {
        const FVector2D& Vi = Vertices[i];
        const FVector2D& Vj = Vertices[j];

        // 이 변이 Point의 Y높이를 지나가는지, 지나간다면 X 교차점이 Point보다 오른쪽인지 확인
        bool bYCrosses = ((Vi.Y > Point.Y) != (Vj.Y > Point.Y));
        if (bYCrosses)
        {
            float IntersectX = Vi.X + (Point.Y - Vi.Y) * (Vj.X - Vi.X) / (Vj.Y - Vi.Y);
            if (Point.X < IntersectX)
            {
                bInside = !bInside;   // 교차할 때마다 안/밖을 뒤집는다
            }
        }
    }

    return bInside;
}
```

### 2-3. Winding Number(권취 수) — 개념만 짚고 가기

레이 캐스팅과 비슷한 목적으로 쓰이는 또 다른 방법이 **Winding Number**다. 판정할 점을 중심으로, 다각형의 경계를 따라 한 바퀴 돌 때 그 경계가 점 주위를 **몇 바퀴 감았는지**를 계산한다. 감은 횟수가 0이면 점은 다각형 밖, 0이 아니면 안이다.

레이 캐스팅이 "교차 횟수의 홀짝"을 보는 것과 달리, Winding Number는 "각도 변화의 총합"을 적분하듯 계산하는 방식이라 자기 자신과 교차하는 다각형(별 모양 등)에서 더 정교하게 안/밖을 구분할 수 있다. 실무에서 일반적인 게임 로직(존 판정, 클릭 판정)에는 레이 캐스팅으로 충분한 경우가 대부분이라, Winding Number는 "이런 방법도 있다" 정도로 알아두면 된다 — 실제 구현이 필요하면 그때 각 변과 점이 이루는 각도를 내적/외적으로 누적 계산하는 방식으로 확장한다.

### 2-4. 3D 게임에서는 2D로 투영해서 판정한다

게임은 3D인데 왜 이 강의는 계속 `FVector2D`를 썼을까? 실무에서 "지면 위의 구역"(안전지대, 스킬 범위 등)은 대부분 **높이(Z)는 무시하고 XY 평면 기준으로만** 판정한다. 3D 점을 판정하려면 먼저 관심 있는 평면(보통 XY)으로 투영한 다음, 위에서 배운 2D 알고리즘을 그대로 적용하면 된다.

```cpp
bool IsActorInZone(AActor* Actor, const TArray<FVector2D>& ZoneVertices2D)
{
    FVector Location3D = Actor->GetActorLocation();
    FVector2D Location2D = FVector2D(Location3D.X, Location3D.Y);   // Z 무시, XY만 투영
    return IsPointInPolygonRayCast(Location2D, ZoneVertices2D);
}
```

## 4. 코드로 — 실제 사례: 안전 구역 이탈 감지

```cpp
void ASafeZoneVolume::Tick(float DeltaTime)
{
    Super::Tick(DeltaTime);

    for (APawn* Player : GetOverlappingPawnsCandidates())
    {
        FVector Location3D = Player->GetActorLocation();
        FVector2D Location2D = FVector2D(Location3D.X, Location3D.Y);

        bool bInsideZone = IsPointInPolygonRayCast(Location2D, ZoneBoundary2D);

        if (!bInsideZone && bWasInsideLastFrame[Player])
        {
            OnPlayerLeftSafeZone(Player);   // 안전 구역 이탈 이벤트
        }

        bWasInsideLastFrame[Player] = bInsideZone;
    }
}
```

배틀로얄 게임의 "자기장(Zone)" 밖으로 나갔는지 판정하는 로직도 결국 이 알고리즘의 응용이다 — 다만 실제 자기장은 원형(구체 판정, 7강)인 경우가 많고, 다각형 모양의 특수 구역에서 이 강의의 방법이 쓰인다.

## 5. 흔한 오해

### 오해 1: "외적 부호 판정은 어떤 다각형에도 다 통한다"

외적 부호 판정은 **볼록 다각형**에서만 정확하다. 오목한 부분이 있는 다각형에서는 변마다 "안쪽 방향"의 의미가 달라져서 이 단순 비교가 틀린 결과를 낸다. 오목 다각형이면 레이 캐스팅이나 Winding Number를 써야 한다.

### 오해 2: "레이 캐스팅에서 광선 방향은 아무 상관 없다"

방향 자체는 어느 쪽이든 상관없지만(오른쪽이든 왼쪽이든), **일관되게 하나의 방향**을 써야 하고 구현 내내 그 기준을 유지해야 한다. 또한 광선이 다각형의 꼭짓점을 정확히 스치는 경계 케이스(부동소수점 오차)는 별도로 주의해서 처리해야 한다.

### 오해 3: "3D 게임이니까 판정도 3D로 해야 정확하다"

지면 위의 구역처럼 "높이는 상관없고 평면상의 위치만" 의미 있는 경우가 대부분이다. 이럴 땐 오히려 3D로 그대로 판정하려는 게 불필요하게 복잡하고, 관심 평면으로 투영해서 2D로 판정하는 게 맞다.

### 오해 4: "교차 횟수가 홀수/짝수인 걸로 안/밖을 판정하는 게 뭔가 임시방편 같다"

수학적으로 탄탄한 근거가 있는 방법이다. 점에서 무한대로 뻗는 광선이 다각형 경계를 지날 때마다 "안/밖"이라는 상태가 정확히 한 번씩 뒤집힌다는 사실은 다각형의 볼록/오목 여부와 무관하게 항상 성립하기 때문에, 오히려 볼록 다각형 전용 외적 부호 판정보다 일반적이고 견고한 방법이다.

## 6. 면접에서 나오면

**Q1. 점이 다각형 내부에 있는지 어떻게 판정하나요?**
→ "대표적으로 두 가지 방법이 있습니다. 볼록 다각형이면 각 변에 대해 외적의 부호가 일관되게 같은 쪽인지 확인하고, 오목 다각형까지 다뤄야 하면 점에서 광선을 쏴서 다각형 경계와 교차하는 횟수가 홀수인지 짝수인지로 판정합니다."

**Q2. 외적 부호로 판정하는 방법의 한계는 뭔가요?**
→ "볼록 다각형에서만 정확합니다. 오목한 다각형은 변마다 안쪽 방향의 의미가 달라져서 부호 비교만으로는 정확한 판정이 안 됩니다."

**Q3. Ray Casting 방식이 왜 홀수/짝수로 안/밖을 구분하나요?**
→ "점에서 뻗은 광선이 다각형 경계를 한 번 지날 때마다 안과 밖이라는 상태가 뒤집히기 때문입니다. 다각형 모양과 무관하게 항상 성립하는 성질이라, 교차 횟수의 홀짝만 세면 내부/외부를 일반적으로 판정할 수 있습니다."

**Q4. 오목 다각형에서 점-다각형 판정을 해야 한다면 어떤 방법을 고르겠어요?**
→ "Ray Casting을 씁니다. 외적 부호 판정은 볼록 다각형 전용이라 오목한 모양에서는 틀린 결과가 나올 수 있고, Ray Casting은 다각형 모양에 상관없이 일반적으로 적용되기 때문입니다."

**Q5. 3D 게임에서 지면 위의 구역 판정을 어떻게 처리하나요?**
→ "높이(Z)는 무시하고 XY 평면으로 투영한 다음, 2D 점-다각형 판정 알고리즘을 그대로 적용합니다. 대부분의 존이나 안전 구역 판정은 실제로 평면상의 위치만 의미가 있기 때문입니다."

**Q6. Winding Number 방식은 Ray Casting과 뭐가 다른가요?**
→ "Ray Casting은 교차 횟수의 홀짝을 보는 방식이고, Winding Number는 다각형 경계가 점 주위를 몇 바퀴 감았는지를 계산하는 방식입니다. 일반적인 존 판정에는 Ray Casting으로 충분하고, Winding Number는 자기 자신과 교차하는 복잡한 다각형에서 더 정교하게 쓰입니다."

**Q7. 2D 외적과 3D 외적은 어떻게 다른가요?**
→ "3D 외적은 결과가 벡터지만, 2D에서 흔히 쓰는 외적은 3D 외적 결과 벡터의 Z 성분만 뽑은 스칼라 값입니다. 2D 평면에서는 그 값의 부호만으로 좌/우, 안/밖 관계를 판정할 수 있어서 이렇게 단순화해서 씁니다."

## 7. 셀프 체크

- [ ] 외적 부호로 볼록 다각형 내부 판정을 구현할 수 있다.
- [ ] 이 방법이 오목 다각형에서 왜 실패하는지 설명할 수 있다.
- [ ] Ray Casting 방식의 원리(교차 횟수 홀짝)를 설명할 수 있다.
- [ ] 3D 좌표를 2D로 투영해서 판정하는 이유와 방법을 안다.
- [ ] Winding Number가 Ray Casting과 어떻게 다른지 개념 수준에서 설명할 수 있다.

## Part 정리 — 게임 수학 8강 총정리

| 강의 | 핵심 개념 | 대표 활용 |
|------|-----------|-----------|
| 1강 | 벡터, 위치/방향/변위 | 이동, 거리 계산 |
| 2강 | 크기, 정규화 | 방향만 필요한 모든 계산의 전처리 |
| 3강 | 내적, 코사인 | 시야각(FOV) 판정, 투영 |
| 4강 | 외적, 사인 | 좌/우 판정, 회전축, 법선 |
| 5강 | 좌표계, FTransform | 부모-자식 계층, 무기 부착 |
| 6강 | Look-At, atan2 | 터렛/카메라 추적 |
| 7강 | 구체/AABB 충돌, 브로드-내로우 페이즈 | 총알-벽 충돌, 폭발 범위 |
| 8강 | 점-다각형 판정 | 존/영역 판정, 클릭 판정 |

여기까지가 게임 클라이언트 개발자가 면접에서 "이 정도는 알아야" 하는 게임 수학의 기본기다. 벡터 하나(1강)에서 시작해서, 그 벡터를 조합하고(내적/외적), 좌표계에 배치하고(변환), 실제 판정 로직(충돌, 다각형)까지 이어지는 흐름을 기억해두면 된다.
