# 1강 — 벡터란 무엇인가

> **목표:** 벡터가 "크기 + 방향"을 나타내는 도구라는 걸 몸에 익히고, 스칼라와 헷갈리지 않게 된다.
> **선수 지식:** 없음. 게임 수학 시리즈의 첫 강의.

---

## 1. 도입 — 캐릭터가 이상한 방향으로 걸어간다

이런 이동 로직을 짰다고 하자.

```cpp
// 목표 지점까지 이동시키고 싶다
void AMyCharacter::MoveTowardTarget(float Speed)
{
    float Distance = FVector::Dist(GetActorLocation(), TargetLocation);
    AddMovementInput(FVector(Speed, 0.0f, 0.0f), 1.0f);   // ???
}
```

`Speed`는 그냥 숫자다. 200이든 500이든, 그 자체로는 "얼마나 빠른가"만 말해줄 뿐 "어느 쪽으로"는 아무것도 말해주지 않는다. 그래서 위 코드는 캐릭터를 항상 월드 X축 방향으로만 밀어버린다. 목표가 어디 있든 상관없이.

플레이어가 진짜로 원하는 건 "목표 지점 쪽으로" 가는 것이다. 이걸 표현하려면 숫자 하나(크기)로는 안 되고, "어느 방향으로 얼마나"라는 두 가지 정보가 같이 필요하다. 이게 벡터다.

```cpp
// 올바른 버전
FVector ToTarget = TargetLocation - GetActorLocation();   // 방향 + 거리를 담은 벡터
FVector Direction = ToTarget.GetSafeNormal();              // 방향만 뽑아냄
AddMovementInput(Direction, 1.0f);
```

이 강의는 이 `ToTarget`, `Direction` 같은 것들이 정확히 뭔지, 어떻게 다루는지에서 시작한다.

---

## 2. 개념 설명

### 2-1. 스칼라 vs 벡터

- **스칼라(Scalar):** 크기만 있는 값. 방향이 없다.
  - 예: HP(100), 데미지(30), 시간(0.5초), 질량(80kg)
- **벡터(Vector):** 크기 **+ 방향**이 있는 값.
  - 예: 이동 속도(초당 500cm, 정면 방향으로), 힘(중력, 아래 방향으로 9.8), 위치(원점에서 어느 방향으로 얼마나 떨어져 있는가)

`float Speed = 500.0f;`는 스칼라다. "얼마나 빠른가"만 있다. `FVector Velocity = FVector(500, 0, 0);`는 벡터다. "얼마나 빠르게, 어느 쪽으로"가 다 들어있다.

헷갈리는 사람들이 자주 하는 실수: 게임에서 흔히 쓰는 "Speed"라는 이름 때문에 스칼라와 벡터를 섞어 쓴다. 언리얼 캐릭터 무브먼트의 `MaxWalkSpeed`는 스칼라(float)고, 실제 이동에 쓰이는 `Velocity`는 벡터(FVector)다. 이 둘의 역할이 다르다는 걸 명확히 구분해야 한다.

### 2-2. FVector의 정체

언리얼의 `FVector`는 그냥 실수 3개를 묶은 구조체다.

```cpp
struct FVector
{
    float X, Y, Z;
};
```

이 3개의 숫자가 뭘 의미하는지는 **문맥에 따라 완전히 다르다.**

| 문맥 | 의미 |
|------|------|
| `GetActorLocation()`의 반환값 | 월드 원점에서 이 액터까지의 **위치** |
| `GetActorForwardVector()`의 반환값 | 액터가 바라보는 **방향** (크기는 항상 1) |
| `Velocity` | 이동 **속도**: 방향 + 초당 이동 거리 |
| `TargetLocation - MyLocation` | 두 지점 사이의 **변위(Displacement)**: 방향 + 거리 |
| 물리 엔진의 `AddForce` 인자 | 가해지는 **힘**: 방향 + 세기 |

즉 `FVector`는 그릇일 뿐이고, 그 안에 위치를 담을 수도, 방향을 담을 수도, 속도나 힘을 담을 수도 있다. 코드만 보고 "이 FVector가 지금 뭘 의미하는가"를 파악하는 게 실무에서 은근히 중요하다 — 변수명을 `Direction`, `Location`, `Velocity`처럼 의미가 드러나게 짓는 이유가 여기 있다.

### 2-3. 벡터의 세 가지 얼굴 — 위치, 방향, 변위

같은 `FVector` 타입이지만 역할이 다른 세 가지를 구분해서 알아야 한다.

**위치 벡터(Position Vector)** — 원점(0,0,0)에서 어떤 점까지의 벡터. `GetActorLocation()`이 반환하는 값.

**방향 벡터(Direction Vector)** — 크기가 1로 정규화된, "어느 쪽"만 의미 있는 벡터. `GetActorForwardVector()`, `GetActorUpVector()` 등.

**변위 벡터(Displacement Vector)** — 두 위치의 차이. `B - A`는 "A에서 B로 가는 벡터"다. 시작점이 어디든 상관없이 방향과 거리만 의미를 갖는다.

```cpp
FVector PlayerPos = FVector(100, 0, 0);     // 위치
FVector EnemyPos  = FVector(400, 300, 0);   // 위치

FVector ToEnemy = EnemyPos - PlayerPos;      // 변위: 플레이어에서 적까지
float DistanceToEnemy = ToEnemy.Size();      // 변위의 크기 = 거리
FVector DirToEnemy = ToEnemy.GetSafeNormal(); // 변위의 방향만 = 방향 벡터
```

여기서 중요한 포인트: **변위 벡터는 위치가 아니다.** `ToEnemy`를 그대로 `SetActorLocation()`에 넣으면 안 된다. 그건 원점 기준 좌표가 아니라 "얼마나 이동해야 하는가"라는 상대적인 정보이기 때문이다.

### 2-4. 벡터 기본 연산이 게임에서 의미하는 것

| 연산 | 수식 | 게임에서의 의미 |
|------|------|----------------|
| 덧셈 | `A + B` | 이동을 순서대로 두 번 적용한 결과 (합성 이동) |
| 뺄셈 | `B - A` | A에서 B로 가는 방향+거리 (변위) |
| 스칼라 곱 | `V * t` | 속도 벡터에 시간을 곱하면 이동 거리 (등속 운동) |
| 스칼라 곱(음수) | `V * -1` | 정반대 방향 |

```cpp
// 등속 이동: 위치 = 이전 위치 + 속도 * 시간
FVector NewLocation = OldLocation + Velocity * DeltaTime;

// 넉백: 맞은 방향의 반대쪽으로 밀려남
FVector KnockbackDir = -HitDirection;
FVector KnockbackForce = KnockbackDir * KnockbackPower;
```

`NewLocation = OldLocation + Velocity * DeltaTime`은 사실상 모든 언리얼 캐릭터 이동, 투사체 이동의 뼈대다. `Tick(float DeltaTime)` 함수 안에서 매 프레임 이 계산이 일어난다고 보면 된다.

### 2-5. FVector2D, FVector, FVector4 — 언제 뭘 쓰나

언리얼에는 벡터 타입이 여러 개 있고, 차원 수만 다른 게 아니라 **쓰이는 맥락**이 다르다.

| 타입 | 성분 | 대표 용도 |
|------|------|----------|
| `FVector2D` | X, Y | UI 좌표, 화면 좌표, 8강의 점-다각형 판정처럼 높이를 무시한 평면 계산 |
| `FVector` | X, Y, Z | 월드 공간의 위치·방향·속도 (이 시리즈에서 계속 쓰는 기본형) |
| `FVector4` | X, Y, Z, W | 동차좌표(Homogeneous Coordinate). 렌더링 파이프라인 내부에서 위치와 방향을 구분하는 용도 |

`FVector4`의 `W` 값이 왜 필요한지는 그래픽스 파이프라인까지 들어가야 하는 깊은 주제지만, 감만 잡아두면 좋다: **W=1이면 위치, W=0이면 방향**을 뜻하는 관례가 있다. 위치는 이동(Translation)의 영향을 받아야 하지만 방향은 받으면 안 되는데, 행렬 변환 계산에서 이 둘을 구분하기 위해 4번째 성분을 쓰는 것이다. 실무 게임플레이 코드에서 `FVector4`를 직접 다룰 일은 많지 않고, 대부분 `FVector`(3D)로 충분하다.

## 3. 그림으로 보면 — 좌표계와 벡터

```
        Z (Up)
        │
        │      ● EnemyPos (400, 300, 0)
        │     ╱
        │    ╱  ← ToEnemy = EnemyPos - PlayerPos
        │   ╱
        │  ●  PlayerPos (100, 0, 0)
        │ ╱
        │╱________________ Y
       ╱
      ╱
     X
```

언리얼은 **왼손 좌표계**를 쓰고, **Z축이 위쪽(Up)**이다. (수학 교과서에서 흔히 보는 Y-up 오른손 좌표계와 다르다.) 단위는 기본적으로 **cm**다. `FVector(100, 0, 0)`은 원점에서 X축 방향으로 1m 떨어진 위치라는 뜻이다.

## 4. 코드로 — 실제 사례: 근접 공격 범위 판정

```cpp
bool AMyCharacter::IsTargetInAttackRange(AActor* Target, float AttackRange) const
{
    if (!Target)
    {
        return false;
    }

    // 변위 벡터: 나에서 타겟까지
    FVector ToTarget = Target->GetActorLocation() - GetActorLocation();

    // 변위 벡터의 크기 = 거리
    float DistanceToTarget = ToTarget.Size();

    return DistanceToTarget <= AttackRange;
}
```

`ToTarget`은 변위 벡터, `ToTarget.Size()`는 그 벡터의 크기(스칼라)다. "벡터에서 스칼라를 뽑아낸다"는 감각을 여기서 처음 잡고 가면 된다 — 다음 강의(정규화)에서 계속 쓰인다.

## 5. 흔한 오해

### 오해 1: "벡터는 화살표 그림일 뿐이다"

화살표는 벡터를 눈에 보이게 그린 것일 뿐, 벡터의 본질은 **숫자의 순서쌍**이다. `FVector(3, 4, 0)`은 원점에서 시작하든 (10,10,0)에서 시작하든 "X로 3, Y로 4만큼"이라는 같은 의미를 갖는다. 시작점은 벡터 자체의 정보가 아니다.

### 오해 2: "FVector 세 개짜리 값은 다 위치다"

앞서 봤듯 방향, 속도, 힘, 변위 전부 `FVector`로 표현된다. 코드에서 `FVector`를 보면 "이게 위치인지 방향인지 속도인지"를 변수명과 문맥으로 먼저 파악해야 한다.

### 오해 3: "벡터끼리는 그냥 곱하면 된다"

`FVector`에는 일반적인 `*` 연산자가 있긴 하지만, 이건 **컴포넌트별 곱셈**(`(A.X*B.X, A.Y*B.Y, A.Z*B.Z)`)이지 수학적으로 의미 있는 "벡터의 곱"이 아니다. 벡터끼리 의미 있게 곱하는 방법은 내적과 외적, 두 가지뿐이고 이건 각각 3강, 4강에서 다룬다.

### 오해 4: "정규화 안 해도 방향은 방향이다"

방향을 나타내려고 `TargetLocation - MyLocation`을 그대로 쓰면, 이 벡터의 크기는 "둘 사이의 거리"가 되어버린다. 방향'만' 필요한 계산(이동 입력, 회전 계산 등)에 크기가 제각각인 벡터를 넣으면 결과가 왜곡된다. 이 문제와 해결법(정규화)은 다음 강의에서 바로 다룬다.

## 6. 면접에서 나오면

**Q1. 벡터와 스칼라의 차이가 뭔가요?**
→ "스칼라는 크기만 있는 값이고, 벡터는 크기와 방향을 같이 갖는 값입니다. 예를 들어 데미지 30은 스칼라고, 이동 속도는 '초당 500cm, 정면 방향으로'처럼 방향이 있으니 벡터입니다."

**Q2. 언리얼에서 FVector는 어떻게 구성되나요?**
→ "X, Y, Z 세 개의 float으로 구성된 구조체입니다. 다만 이 세 값이 항상 위치를 의미하는 건 아니고, 문맥에 따라 위치·방향·속도·힘을 전부 표현할 수 있습니다."

**Q3. 두 위치 벡터를 빼면 뭐가 나오나요?**
→ "변위 벡터가 나옵니다. A에서 B로 가는 방향과 거리를 담고 있는 벡터라서, 두 오브젝트 사이 거리를 구하거나 상대 방향을 구할 때 씁니다."

**Q4. 방향 벡터와 위치 벡터를 같은 방식으로 다뤄도 되나요?**
→ "안 됩니다. 위치 벡터는 원점 기준 절대 좌표고, 방향 벡터는 크기가 1로 정규화된, 방향만 의미 있는 벡터입니다. 변위 벡터를 그대로 위치에 대입하면 엉뚱한 좌표가 나옵니다."
> 면접관이 그 다음에 던지기 좋은 질문: "그럼 방향만 필요할 땐 어떻게 처리하나요?" → 정규화(Normalize) 개념으로 이어진다. (2강)

**Q5. 언리얼 좌표계는 일반적인 수학 좌표계와 뭐가 다른가요?**
→ "언리얼은 왼손 좌표계를 쓰고 Z축이 위쪽(Up)입니다. 수학이나 유니티에서 흔히 보는 오른손 좌표계, Y-up과는 다르기 때문에 좌표계를 넘나드는 툴 연동할 때는 이 차이를 주의해야 합니다."

**Q6. 캐릭터가 목표 지점으로 이동하는 로직을 벡터로 어떻게 짜겠어요?**
→ "목표 위치에서 현재 위치를 빼서 변위 벡터를 구하고, 그걸 정규화해서 방향만 뽑은 다음, `AddMovementInput`에 그 방향 벡터를 넘깁니다. 거리 값이 필요하면 정규화 전 변위 벡터의 크기를 따로 씁니다."

**Q7. 속도(Velocity)와 속력(Speed)을 구분해서 설명해줄 수 있나요?**
→ "속력은 스칼라로, 얼마나 빠른가만 나타냅니다. 속도는 벡터로, 속력과 방향을 같이 갖습니다. 언리얼의 `MaxWalkSpeed`는 스칼라고, 실제 이동에 쓰이는 `Velocity`는 벡터인 게 그 차이를 보여주는 예입니다."

## 7. 셀프 체크

- [ ] 스칼라와 벡터의 차이를 예시와 함께 설명할 수 있다.
- [ ] `FVector` 하나가 위치·방향·속도·힘 등 여러 의미로 쓰일 수 있다는 걸 안다.
- [ ] 두 위치의 차(`B - A`)가 변위 벡터라는 걸 알고, 그 크기가 거리라는 걸 계산할 수 있다.
- [ ] 언리얼 좌표계가 왼손 좌표계이고 Z-up이라는 걸 안다.
- [ ] 방향 벡터와 위치 벡터를 혼동하면 안 되는 이유를 설명할 수 있다.
