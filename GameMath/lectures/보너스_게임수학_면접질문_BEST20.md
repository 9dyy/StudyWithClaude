# 보너스 — 게임 수학 면접 질문 BEST 20

> 8강까지 배운 내용을 실제 면접 질문 형태로 재정리한다. 답은 입으로 바로 말할 수 있는 수준의 구어체로 적었다.
> 형식은 존댓말(실제 면접 답변 톤)로 통일한다.

---

## Part A. 벡터 기초 (1~2강)

**Q1. 벡터와 스칼라의 차이가 뭔가요?**
→ "스칼라는 크기만 있는 값이고 벡터는 크기와 방향을 같이 갖는 값입니다. 데미지나 HP는 스칼라고, 속도나 힘은 방향이 있으니 벡터입니다."

**Q2. FVector 하나가 항상 위치를 의미하나요?**
→ "아니요. 같은 FVector 타입이라도 문맥에 따라 위치, 방향, 속도, 힘을 전부 표현할 수 있습니다. 변수명과 문맥으로 구분해야 합니다."

**Q3. 정규화가 뭐고 왜 필요한가요?**
→ "벡터를 자기 크기로 나눠서 방향은 유지하고 크기만 1로 만드는 연산입니다. 이동 입력처럼 방향만 필요한 자리에 크기가 제각각인 벡터를 그대로 쓰면, 대각선 이동이 더 빨라지는 것 같은 버그가 생기기 때문에 정규화가 필요합니다."

**Q4. Normalize()와 GetSafeNormal()의 차이는요?**
→ "Normalize()는 크기가 0에 가까우면 0으로 나누기가 발생해서 NaN이 나올 수 있습니다. GetSafeNormal()은 이 경우를 감지해서 0벡터를 안전하게 반환합니다. 실무에서는 거의 항상 GetSafeNormal()을 씁니다."

**Q5. 거리 비교할 때 왜 SizeSquared를 쓰나요?**
→ "제곱근 연산이 비교적 비싼 연산이라, 단순히 대소만 비교할 거면 제곱값끼리 비교해도 결과가 같기 때문입니다. 거리 비교가 많은 로직(가장 가까운 적 찾기 등)에서 성능 차이가 실제로 납니다."

## Part B. 내적과 외적 (3~4강)

**Q6. 내적이 뭔가요?**
→ "두 벡터의 같은 축 성분끼리 곱해서 더한 값입니다. 결과는 스칼라이고, 두 벡터를 정규화한 상태에서 내적하면 그 값이 곧 둘 사이 각도의 코사인 값이 됩니다."

**Q7. 내적으로 시야각(FOV) 판정을 어떻게 하나요?**
→ "정면 방향 벡터와 타겟 방향 벡터를 정규화해서 내적을 구하고, 원하는 시야각의 코사인 값과 비교합니다. 각도가 커질수록 코사인 값은 작아진다는 걸 기억해야 부등호 방향을 안 틀립니다."

**Q8. 외적이 뭔가요?**
→ "두 벡터로부터 그 둘 모두에 수직인 새 벡터를 만드는 연산입니다. 내적은 결과가 스칼라지만 외적은 결과가 벡터라는 게 가장 큰 차이입니다."

**Q9. 외적으로 좌/우를 어떻게 판정하나요?**
→ "정면 벡터와 타겟 방향 벡터를 외적하면, 결과 벡터의 특정 축(언리얼 기준 Z) 부호로 좌/우를 판정할 수 있습니다. 단, 외적은 인자 순서를 바꾸면 결과가 반대 방향이 되니 순서를 일관되게 써야 합니다."

**Q10. 내적과 외적을 각각 언제 쓰나요?**
→ "'얼마나 같은 방향인가'처럼 각도 크기 자체가 중요할 때는 내적을, '어느 쪽으로 치우쳤는가'나 회전축처럼 방향의 부호나 수직 방향이 필요할 때는 외적을 씁니다."

## Part C. 좌표계와 회전 (5~6강)

**Q11. 월드 좌표와 로컬 좌표의 차이가 뭔가요?**
→ "월드 좌표는 레벨 원점 기준 절대 위치고, 로컬 좌표는 부모나 소켓 같은 기준점에 대한 상대 위치입니다. 무기를 손 소켓에 붙일 때 로컬 좌표를 고정해두면, 캐릭터가 움직여도 월드 좌표만 자동으로 재계산되면서 손을 따라다닙니다."

**Q12. FTransform은 뭘 담고 있나요?**
→ "위치, 회전, 스케일 세 가지를 하나로 묶은 구조체입니다. 이 셋을 합치면 한 좌표계를 다른 좌표계로 바꾸는 변환 전체를 표현할 수 있습니다."

**Q13. 카메라나 몬스터가 특정 지점을 바라보게 하려면 회전값을 어떻게 구하나요?**
→ "목표 지점에서 현재 위치를 빼서 방향 벡터를 구하고 정규화한 다음, 그 벡터를 회전값으로 변환합니다. 언리얼의 FindLookAtRotation이 이 과정을 대신해줍니다."

**Q14. FindLookAtRotation은 내부적으로 어떻게 동작하나요?**
→ "방향 벡터를 구해서 정규화하고, 그 벡터의 X, Y, Z 성분을 atan2 기반으로 Yaw와 Pitch로 변환합니다. Roll은 방향 벡터만으로는 결정되지 않아서 보통 0으로 둡니다."

**Q15. 캐릭터가 위/아래를 볼 때 몸통까지 숙여지면 이상한데 어떻게 처리하나요?**
→ "몸통 회전에는 Pitch를 0으로 고정해서 좌우 회전(Yaw)만 적용하고, 실제 시선 방향은 카메라나 머리 본 같은 별도 요소에 반영합니다."

## Part D. 충돌과 판정 (7~8강)

**Q16. 물체 간 충돌은 어떻게 감지하나요?**
→ "메시 원본 형태 대신 구체나 박스처럼 단순화된 콜리전 도형으로 겹침을 계산합니다. 구체는 중심 거리와 반지름 합을 비교하고, AABB는 각 축의 최소/최대값이 겹치는지 확인합니다."

**Q17. 브로드 페이즈와 내로우 페이즈가 왜 나뉘나요?**
→ "오브젝트가 많을 때 모든 쌍을 정밀 검사하면 계산량이 너무 커지기 때문입니다. 먼저 싼 연산(AABB 등)으로 겹칠 가능성이 있는 쌍만 걸러내고, 그 소수만 정밀하게 검사해서 전체 연산량을 줄입니다."

**Q18. 점이 다각형 내부에 있는지 어떻게 판정하나요?**
→ "볼록 다각형이면 각 변에 대해 외적 부호가 일관되게 같은 쪽인지 확인합니다. 오목 다각형까지 다뤄야 하면 점에서 광선을 쏴서 다각형 경계와 교차하는 횟수가 홀수인지 짝수인지로 판정합니다."

**Q19. Ray Casting 방식이 왜 홀수/짝수로 안/밖을 구분하나요?**
→ "점에서 뻗은 광선이 다각형 경계를 한 번 지날 때마다 안과 밖이 뒤집히기 때문입니다. 다각형 모양과 무관하게 항상 성립해서, 교차 횟수의 홀짝만 세면 일반적으로 판정할 수 있습니다."

**Q20. 성능이 중요한 상황에서 충돌 판정 방식을 어떻게 고르겠어요?**
→ "가능한 한 싼 도형부터 씁니다. 대략적인 범위 판정은 구체나 AABB로 충분하고, 실제 정확한 충돌 지점이 필요한 마지막 단계에서만 정밀 충돌을 씁니다. 처음부터 모든 오브젝트에 정밀 메시 충돌을 매 프레임 돌리는 건 낭비입니다."

## 면접 직전 30초 암기 카드

| 키워드 | 한 줄 요약 |
|--------|-----------|
| 벡터 vs 스칼라 | 방향 있으면 벡터, 없으면 스칼라 |
| 정규화 | 방향 유지, 크기만 1로. GetSafeNormal 써라 |
| 내적 | 정규화된 벡터끼리면 결과 = cos(각도) |
| 외적 | 결과는 벡터, 두 벡터 모두에 수직, 순서 바꾸면 반대 방향 |
| 내적 용도 | 시야각(FOV) 판정, 투영 |
| 외적 용도 | 좌/우 판정, 회전축, 법선 |
| 월드 vs 로컬 좌표 | 절대 위치 vs 부모 기준 상대 위치 |
| FTransform | 위치 + 회전 + 스케일 |
| Look-At | 방향 벡터 → atan2 → Yaw/Pitch (Roll은 별도) |
| 구체 충돌 | 중심 거리 <= 반지름 합 |
| AABB 충돌 | 세 축 모두 겹쳐야 충돌 |
| 브로드/내로우 페이즈 | 싼 필터링 먼저, 비싼 정밀 검사는 나중에 |
| 점-다각형 (볼록) | 외적 부호가 모든 변에서 일관되면 내부 |
| 점-다각형 (오목까지) | Ray Casting, 교차 횟수 홀수면 내부 |
