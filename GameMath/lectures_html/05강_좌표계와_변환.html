Part 3 · 좌표계와 회전

좌표계와 변환

캐릭터가 걸어가는데 무기는 제자리에 남는다. 월드 좌표와 로컬 좌표를 왜 나누는지, FTransform이 뭘 하는지 캐릭터를 직접 돌리고 움직이며 확인한다.

🌐 월드 ↔ 로컬
🧩 선수지식 1~4강
⏱️ 약 25분
SECTION 01 · 도입

1캐릭터 손에 든 무기가 자꾸 이상한 위치에 붙는다

Weapon->AttachToComponent(Mesh, FAttachmentTransformRules::KeepRelativeTransform, TEXT("hand_r_socket"));

여기서 "Relative"가 왜 필요할까? 무기 위치를 월드 좌표로 고정해 손에 붙이면 캐릭터가 걸어가는 순간 무기는 원래 자리에 남고 손만 무기 없이 움직인다. 무기가 손을 따라다니게 하려면 위치를 월드 원점이 아니라 손(소켓) 기준으로 표현해야 한다 — 이게 로컬 좌표다.

SECTION 02 · 핵심 · 직접 돌려보기

2트랜스폼 놀이터 — 캐릭터를 움직이고 돌려보자

캐릭터(파란 상자)를 움직이고 돌리면 월드 좌표만 바뀌고 무기의 로컬 좌표는 그대로다. 토글로 "월드 고정 부착"과 "잘못된 변환 순서"를 켜서 버그를 재현하고, 빈 곳을 클릭해 폭발을 놓으면 캐릭터 기준 앞/뒤를 로컬 좌표로 판정한다.

무기 부착
변환 순서
Weapon 로컬 좌표 (GetRelativeLocation)
Weapon 월드 좌표 (GetComponentLocation)
폭발 월드 좌표
폭발 로컬 좌표 (InverseTransformPosition)

① 슬라이더로 캐릭터를 움직여도 Weapon 로컬 좌표는 (10, 24)로 불변, 월드 좌표만 재계산된다. ② "월드 좌표로 고정"으로 바꾼 뒤 움직이면 무기가 제자리에 남는다. ③ 비균등 스케일을 켠 채 "회전→스케일→이동"을 고르면 상자가 회전을 무시하고 월드 축으로 찌그러지고 무기가 몸에서 떨어진다. ④ 클릭한 폭발 지점의 로컬 X 부호가 앞/뒤다.

SECTION 03 · 개념

3월드 좌표 vs 로컬 좌표

월드 좌표 (World Space)

레벨 전체의 원점(0,0,0) 기준 절대 위치. GetActorLocation()

로컬 좌표 (Relative Space)

부모(액터, 컴포넌트, 소켓) 기준 상대 위치. GetRelativeLocation()

FVector WeaponWorldLocation = Weapon->GetComponentLocation();   // 월드 기준 실제 위치
FVector WeaponLocalLocation = Weapon->GetRelativeLocation();    // 소켓 기준 상대 위치 (10, 0, 5) — 불변

KeepRelativeTransform으로 붙이면 무기의 로컬 좌표는 고정되고 부모가 움직이거나 회전할 때마다 월드 좌표만 자동으로 재계산된다. 이게 자식이 부모를 따라다니는 원리다.

SECTION 04 · FTransform

4위치·회전·스케일을 하나로 — 그리고 변환 순서

struct FTransform
{
    FQuat   Rotation;      // 회전
    FVector Translation;   // 위치(이동)
    FVector Scale3D;       // 크기
};

FTransform ActorTransform = GetActorTransform();
FVector WorldPoint = ActorTransform.TransformPosition(FVector(1, 0, 0));   // 로컬 → 월드

이 세 값이 "한 좌표계를 다른 좌표계로 바꾸는 변환" 하나를 표현한다. 로컬 → 월드 순서는:

월드 좌표 = 이동( 회전( 스케일( 로컬 좌표 ) ) )

스케일을 먼저 해야 "그 축 방향으로 늘어난 상태"에서 회전이 걸리고, 회전이 끝난 뒤에 최종 위치로 옮긴다. 순서를 바꾸면 결과가 완전히 달라진다 — 시뮬레이터의 "회전→스케일" 버그가 바로 그것이다. 비균등 스케일 오브젝트를 회전시켰더니 찌그러져 보이는 버그는 종종 이 순서 문제에서 나온다. TransformPosition/InverseTransformPosition이 이 계산을 알아서 처리해주니 직접 행렬 곱셈을 짤 필요는 없다.

SECTION 05 · 계층 구조

5부모-자식 변환 — 계층이 쌓일 때

// 캐릭터 → 손 소켓 → 무기 메시 → 무기에 붙은 이펙트
월드(이펙트) = 월드(캐릭터) × 로컬(손 소켓) × 로컬(무기) × 로컬(이펙트)

FTransform ChildWorldTransform = ChildComponent->GetComponentTransform();
// 내부적으로 부모의 월드 트랜스폼 + 자신의 RelativeTransform을 합성해 계산

각 단계는 바로 위 부모 기준 로컬 트랜스폼만 알면 된다. 캐릭터 하나만 움직여도 무기·이펙트·파티클까지 자동으로 따라온다 — 월드 좌표를 매번 다시 넣어줄 필요가 없다.

SECTION 06 · 역변환

6월드 → 로컬 — "폭발이 캐릭터 앞인가 뒤인가"

FVector ExplosionWorldLocation = ...;
FTransform CharTransform = GetActorTransform();
FVector LocalExplosion = CharTransform.InverseTransformPosition(ExplosionWorldLocation);

bool bInFront = LocalExplosion.X > 0.0f;   // 로컬 X가 양수면 앞, 음수면 뒤

3·4강에서 내적/외적으로 앞/뒤, 좌/우를 판정한 것과 목적이 같다. 다만 로컬 변환은 앞/뒤뿐 아니라 "로컬 좌표계에서 정확히 어디인지"까지 한 번에 준다. 시뮬레이터에서 폭발을 여러 곳에 클릭해보자.

SECTION 07 · 회전 합성

7회전 합성에 오일러 각 대신 쿼터니언을 쓰는 이유

짐벌락 (Gimbal Lock)

Pitch ±90° 같은 각도에서 회전축 하나가 다른 축과 겹쳐 자유도 하나를 잃는 현상. 위/아래를 볼 때 카메라가 홱 돌아가는 버그.

보간의 부자연스러움

오일러 각을 축마다 선형 보간하면 최단 경로가 아니고 흔들린다.

FQuat

합성은 QuatA * QuatB, 보간은 FQuat::Slerp — 항상 최단 경로.

FTransform은 회전을 FQuat으로 저장하고, FRotator는 사람이 읽고 입력하기 편한 겉모습일 뿐이다. 회전을 직접 합성할 땐 FRotator끼리 더하고 빼지 말고 FQuat 연산이 정석.

SECTION 08 · 실전

8카메라 방향으로, 총구 위치에서 발사

void AMyCharacter::FireWeapon()
{
    FVector MuzzleWorldLocation = WeaponMesh->GetSocketLocation(TEXT("Muzzle"));   // 계층을 따라 자동 계산된 "월드" 위치
    FVector CameraForward       = CameraComponent->GetForwardVector();                 // 카메라가 보는 "월드" 방향

    FActorSpawnParameters SpawnParams;
    GetWorld()->SpawnActor<AProjectile>(ProjectileClass, MuzzleWorldLocation, CameraForward.Rotation(), SpawnParams);
}

GetSocketLocation()이 캐릭터 → 무기 메시 → 소켓의 로컬 트랜스폼들을 전부 곱해 월드 좌표 하나로 환산해준다. 이 계산을 직접 짤 필요가 없다는 게 FTransform/소켓 시스템의 실질적 이득이다.
