Part 1 · 벡터 기초 · 게임 수학의 언어

벡터란 무엇인가

캐릭터가 목표와 상관없이 항상 X축으로만 걸어간다. "크기 + 방향"이라는 벡터의 정체와, 같은 FVector가 위치·방향·변위로 어떻게 달라지는지 직접 움직여본다.

➡️ 크기 + 방향
🧩 선수지식 없음
⏱️ 약 20분
SECTION 01 · 도입

1캐릭터가 이상한 방향으로 걸어간다

void AMyCharacter::MoveTowardTarget(float Speed)
{
    AddMovementInput(FVector(Speed, 0.0f, 0.0f), 1.0f);   // ???  Speed는 그냥 숫자 — "얼마나"만 있고 "어느 쪽"이 없다
}

// 올바른 버전
FVector ToTarget  = TargetLocation - GetActorLocation();   // 방향 + 거리를 담은 벡터
FVector Direction = ToTarget.GetSafeNormal();              // 방향만 뽑아냄
AddMovementInput(Direction, 1.0f);

위 코드는 목표가 어디 있든 캐릭터를 항상 월드 X축으로만 민다. 원하는 건 "어느 방향으로 얼마나" — 숫자 하나로는 안 되고 두 정보가 함께 필요하다. 이게 벡터다.

SECTION 02 · 개념

2스칼라 vs 벡터, 그리고 FVector의 정체

스칼라 (Scalar)

크기만 있는 값. HP(100), 데미지(30), 시간(0.5초), 질량(80kg). float Speed = 500.0f;

벡터 (Vector)

크기 + 방향이 있는 값. 이동 속도, 힘, 위치, 변위. FVector Velocity = FVector(500, 0, 0);

언리얼 캐릭터 무브먼트의 MaxWalkSpeed는 스칼라(속력), 실제 이동에 쓰이는 Velocity는 벡터(속도)다. 역할이 다르다.

struct FVector { float X, Y, Z; };   // 그냥 실수 3개를 묶은 구조체 — 의미는 문맥이 정한다
문맥의미
GetActorLocation() 반환값월드 원점에서 이 액터까지의 위치
GetActorForwardVector() 반환값액터가 바라보는 방향 (크기는 항상 1)
Velocity이동 속도: 방향 + 초당 이동 거리
TargetLocation - MyLocation두 지점 사이의 변위(Displacement)
AddForce 인자가해지는 힘: 방향 + 세기

FVector는 그릇일 뿐이라 "이 값이 지금 뭘 의미하는가"를 파악하는 게 중요하다 — 변수명을 Direction, Location, Velocity처럼 의미가 드러나게 짓는 이유다.

SECTION 03 · 세 가지 얼굴

3위치 · 방향 · 변위

위치 벡터

원점(0,0,0)에서 어떤 점까지. GetActorLocation()

방향 벡터

크기가 1로 정규화된, "어느 쪽"만 의미 있는 벡터. GetActorForwardVector()

변위 벡터

두 위치의 차. B - A는 "A에서 B로 가는 벡터". 시작점과 무관하게 방향·거리만 의미.

FVector PlayerPos = FVector(100, 0, 0);     // 위치
FVector EnemyPos  = FVector(400, 300, 0);   // 위치

FVector ToEnemy       = EnemyPos - PlayerPos;   // 변위: 플레이어에서 적까지
float   DistanceToEnemy = ToEnemy.Size();          // 변위의 크기 = 거리
FVector DirToEnemy    = ToEnemy.GetSafeNormal(); // 변위의 방향만 = 방향 벡터

변위 벡터는 위치가 아니다. ToEnemy를 그대로 SetActorLocation()에 넣으면 안 된다. 원점 기준 좌표가 아니라 "얼마나 이동해야 하는가"라는 상대 정보이기 때문이다 — 아래 놀이터에서 직접 터뜨려보자.

SECTION 04 · 핵심 · 직접 돌려보기

4벡터 놀이터 — 같은 FVector, 다른 의미

플레이어(파랑)와 적(빨강)을 드래그하거나 슬라이더로 움직여보자. 회색은 위치 벡터, 노랑은 변위 벡터 ToEnemy, 초록은 정규화한 방향이다.

PlayerPos (위치)
EnemyPos (위치)
ToEnemy = EnemyPos − PlayerPos (변위)
ToEnemy.Size() (거리, 스칼라)
ToEnemy.GetSafeNormal() (방향)
사거리 판정 (SizeSquared 비교)

① 🧭 한 걸음을 반복하면 플레이어가 적에게 다가간다 — NewLocation = OldLocation + Velocity * DeltaTime. ② ⚠ 버튼은 변위를 위치처럼 넣는 버그: 플레이어가 적과 무관한 엉뚱한 좌표로 순간이동한다. ③ 사거리 판정은 제곱끼리 비교해서 sqrt를 아낀다(2강).

SECTION 05 · 연산

5벡터 기본 연산이 게임에서 의미하는 것

연산수식게임에서의 의미
덧셈A + B이동을 순서대로 두 번 적용한 결과 (합성 이동)
뺄셈B - AA에서 B로 가는 방향+거리 (변위)
스칼라 곱V * t속도 벡터 × 시간 = 이동 거리 (등속 운동)
음수 스칼라 곱V * -1정반대 방향
// 등속 이동: 위치 = 이전 위치 + 속도 * 시간 — 캐릭터/투사체 이동의 뼈대 (Tick에서 매 프레임)
FVector NewLocation = OldLocation + Velocity * DeltaTime;

// 넉백: 맞은 방향의 반대쪽으로
FVector KnockbackForce = (-HitDirection) * KnockbackPower;
SECTION 06 · 타입

6FVector2D, FVector, FVector4 — 언제 뭘 쓰나

타입성분대표 용도
FVector2DX, YUI/화면 좌표, 높이를 무시한 평면 계산(8강 점-다각형)
FVectorX, Y, Z월드 공간의 위치·방향·속도 (이 시리즈의 기본형)
FVector4X, Y, Z, W동차좌표 — 렌더링 파이프라인 내부에서 위치와 방향을 구분

감만 잡자: W=1이면 위치, W=0이면 방향. 위치는 이동(Translation)의 영향을 받아야 하지만 방향은 받으면 안 되는데, 행렬 변환에서 둘을 구분하려고 4번째 성분을 쓴다. 게임플레이 코드에서 FVector4를 직접 다룰 일은 드물다.

SECTION 07 · 좌표계 · 실전

7언리얼 좌표계와 근접 공격 범위 판정

        Z (Up)
        │      ● EnemyPos (400, 300, 0)
        │     ╱  ← ToEnemy = EnemyPos - PlayerPos
        │    ╱
        │   ● PlayerPos (100, 0, 0)
        │╱________________ Y
       ╱
      X

언리얼은 왼손 좌표계 + Z-up이다(수학 교과서·유니티의 Y-up 오른손과 다르다). 단위는 cm — FVector(100, 0, 0)은 X축으로 1m.

bool AMyCharacter::IsTargetInAttackRange(AActor* Target, float AttackRange) const
{
    if (!Target) { return false; }
    FVector ToTarget = Target->GetActorLocation() - GetActorLocation();   // 변위 벡터
    return ToTarget.Size() <= AttackRange;                                 // 변위의 크기(스칼라) = 거리
}
